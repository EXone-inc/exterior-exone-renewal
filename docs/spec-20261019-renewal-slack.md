# Spec: 新テーマのフォーム専用 Slack 通知

- 作成日: 2026-10-19
- 起案: 新テーマのお問い合わせ（個人・法人）を共通の通知先へ、採用エントリーを別の通知先へ連携する。旧テーマと既存フォームの設定は保持する。
- 対象: 取り込み済み `exr_form` 3件。PHP 7.4.33、既存 CF7 / CF7 to Webhook 5.0.0 を維持。
- デザイン元: Figma 対象外。WordPress 標準の管理画面を使用し、公開フォームのデザインは変更しない。
- 本書は秘密の Webhook URL を含めない。実値の取り扱いと本番反映は主担当が行う。

## 1. 目的と範囲

新テーマ用の通知先だけを管理者が設定でき、通常の受付メール・自動返信と合わせて Slack へ通知できるようにする。表示・保存・送信への追加処理は `EXR_COEXISTENCE === true` の新テーマ実行中だけ有効にする。

対象は次の2系統である。

| 管理画面の表示名 | 対象フォーム | 通知先 |
|---|---|---|
| お問い合わせ | 個人 `personal`、法人 `corporate` | 同一の指定 Webhook |
| 採用エントリー | `entry` | 採用用の別 Webhook |

一般的なフォーム編集画面、送信履歴保存、再送キュー、テスト送信ボタンは追加しない。旧テーマ・旧フォーム・既存プラグイン本体・共有 options・メール本文や宛先・投稿状態・取り込み識別メタを変更しない。テーマ切り替え、PHP 更新、プラグイン更新・追加も対象外。

## 2. 確認済みの既存連携

- 既存アダプターは保存データを変えず `exr_form` の複製を CF7 オブジェクトへ渡し、公開送信処理で `submit()` を実行する。
- CF7 to Webhook 5.0.0 は `wpcf7_mail_sent` で送信する。`send_mail` の既定値は無効なので、今回の設定では必ず `'1'` とする。メール送信自体が失敗した場合は、このプラグインの通常の Slack 通知も発火しない。
- プラグインは `custom_body` に JSON と `[field]` 置換を使用できる。ただし値の連鎖置換、配列の文字列への埋め込み、Slack のメンション処理を今回の本文生成に持ち込まない。
- 最終リクエスト引数を変更する `ctz_post_request_args` は `$args, $properties, $contact_form, $hook_url` を受け取る。対象を照合したうえで、許可した送信項目から本文全体を JSON 化できる。
- プラグインの既定エラー処理は Webhook URL・リクエスト本文を通知メールへ含め、すでに成功したメール結果を `mail_failed` に変更し得る。新フォームだけはこの挙動を抑止し、旧フォームのエラー処理を維持する。

## 3. F-01: 新テーマ専用の Slack 通知設定

### 表示面と操作

外観配下に「新テーマの Slack 通知」画面を設ける。既存「新テーマ用コンテンツ」の読み取り専用一覧は維持し、必要なら設定画面へのリンクだけを追加する。

画面にはお問い合わせ・採用エントリーの2欄、設定済み／未設定／無効の状態、通知を有効にする選択、変更用 URL 入力、保存操作を表示する。「通常のメール送信は継続します」「空欄のまま保存すると現在の通知先を保持します」と説明する。無効化は明示操作とし、空欄だけで URL を削除しない。

保持済み URL は固定の伏字または「設定済み」として示す。実値を input value、hidden、HTML、JavaScript、確認画面、通知文、リダイレクト URL に戻さない。エラー時も入力された秘密を再表示しない。

### データの境界

保存時と送信時に、DB上の対象が以下すべてを満たすことを確認する。送信中の CF7 オブジェクトは複製なので、それだけを信頼しない。

- `post_type = exr_form`、`post_status = exr_stored`。
- `_exr_dataset = exterior-exone-renewal:v1`、`_exr_source_status = publish`、`_exr_import_state = complete`。
- 元データの識別子 `_exr_source_key` があり、既存アダプターの公開可能条件を満たす。
- `_exr_form_role` が `personal` / `corporate` / `entry` のいずれかであり、各役割の適格レコードが一意。各 ID は別々で、送信オブジェクトの ID と一致する。

URL や POST で指定された任意 ID を保存対象にしない。新3件の `_ctz_zapier` だけを保存対象にする。識別用メタは各1行を要求し、通知メタは未設定の0行から1行への追加または既存1行の変更だけを認める。対象メタが重複する場合、対象が欠落・重複する場合、変更中に所有条件が変わった場合は保存を止める。

通知有効時は `activate = '1'`、`hook_url = [検証済みURL]`、`send_mail = '1'`。無効時も `send_mail = '1'` を保持する。メソッドは POST、ファイル内容送信なし、追加の特別タグ・ヘッダー・本文テンプレートは空、`error_mails = []` とし、今回扱わない任意送信先や本文設定を残さない。`custom_body` の入力編集は提供しない。

`WPCF7_ContactForm::save()` は使用しない。保存投稿の種別・状態などまで変更するためである。全対象・入力を更新前に検証し、保存結果を照合する。同じお問い合わせ設定を保存する個人・法人の一方だけが変わった状態を成功と表示しない。途中失敗の戻しは今回保存した値と一致する所有変更に限り、競合する変更を上書きしない。

取り込み時の hash や fingerprint を今回の設定変更に合わせて書き換えない。通知設定は取り込み後の独立した変更として扱う。

### URL と秘密

管理権限 `manage_options`、POST、nonce を要求する。URL は厳密に HTTPS の Slack Incoming Webhook とし、正確な `hooks.slack.com` ホストと `/services/` 以下の所定の3要素の形式だけを受け付ける。ユーザー名・パスワード・独自ポート・query・fragment・制御文字・別ホスト・サブドメイン偽装・配列入力を拒否する。パース結果だけでなく入力全体との整合を確認する。

保存済み URL も送信直前に同じ検証を行い、今回の対象フォームに保持された唯一の URL と送信先が一致することを要求する。リダイレクトは追わず、TLS 検証を維持する。不一致の新フォームは外向き送信を止める。旧フォームの処理にはこの制限を適用しない。

実 URL は許可された本番メタ以外のソース、仕様書、テスト fixture、公開配布物、通常ログへ保存しない。検証は架空の値を使用し、外向き HTTP・メールを遮断する。バックアップに実値が含まれる場合は非公開の限定バックアップとして主担当が管理する。

### 通知内容

固定の日本語見出し・項目名と、送信済みデータの次の項目だけを使用する。任意 POST、全メタ、内部 CF7 項目、添付ファイルの内容を丸ごと通知しない。

| 対象 | 通知項目と既存 field |
|---|---|
| 個人 | お問い合わせ先 `store-slug`（既存の許可済み支店名へ変換）、お名前 `your-name`、メール `your-email`、郵便番号 `your-zip`、住所 `your-address`、内容 `your-message` |
| 法人 | ご担当者名 `your-name`、企業名 `your-company`、郵便番号 `your-zip`、住所 `your-address`、電話 `your-tel`、メール `your-email`、内容 `your-message` |
| 採用 | 姓 `your-name-last`、名 `your-name-first`、希望職種 `your-job`、性別 `your-gender`、メール `your-email`、電話 `your-tel`、郵便番号 `your-postcode`、住所 `your-address` / `your-extended-address`、応募メッセージ `your-contact` |

採用の `your-subject` はフォームに存在しないため追加しない。既存の単純な配列回答は要素を文字列として結合し、想定外のネスト・オブジェクトは取り込まない。引用符・改行・日本語を保持して本文全体を一度だけ JSON 化する。`&`・`<`・`>` を Slack 向けに無害化し、リンク自動解析・書式・メンションを無効化する。メンション構文や `[別field]` が入力されても、意図しない通知や値の再置換が起きないことを検証する。長文を安全な上限で省略する場合は省略を明示し、全文は通常メールで確認できることを示す。

新フォームの Slack 失敗は、成功済みの通常メール・自動返信の設定や送信結果を変えない。新フォームと保存 URL の両方が一致する場合だけ `ctz_post_request_ignore_errors` 等の限定処理を適用し、URLや本文を含むプラグイン既定エラーメールを抑止する。通知失敗を成功と報告する独自表示は作らず、今回の画面は通知先の設定状態を示すものとする。自動再送や外部への失敗通知は追加しない。

### 受け入れ基準

- [x] AC-01: 新テーマ・管理者だけが設定画面を表示・保存できる。旧テーマ、通常ローカル運用（共存定数なし／false）、権限なし、GET、不正 nonce では保存も追加送信処理も発生しない。
- [x] AC-02: 個人・法人は共通、採用は別の通知先として保持／変更／無効化できる。375px・1920pxで入力と保存が利用でき、既存 URL が DOM や画面・エラーへ漏れない。
- [x] AC-03: 欠落・重複・別 dataset・未完了・別状態・旧フォーム・偽 ID・重複メタを拒否する。保存前後の差分は適格3件の `_ctz_zapier` だけで、投稿行、メール設定、既存レコード・共有設定は同一。
- [x] AC-04: 有効時の `activate` / `hook_url` / `send_mail` 契約と、一方だけの保存失敗を成功にしない処理を確認する。CF7 `save()` による状態変更は発生しない。
- [x] AC-05: 不正 URL・保存値との不一致・別フォームへの送信先流用を拒否する。有効な問い合わせ2件と採用1件の送信先の対応を、外向き通信を遮断した捕捉結果で確認する。
- [x] AC-06: 各フォームの許可 field だけが日本語の項目名で有効な JSON `text` に入る。引用符、改行、配列、日本語、メンション、`[field]` を含む合成入力で JSON 崩れ・連鎖置換・意図しないメンションが起きない。
- [x] AC-07: 実プラグインの送信 hook を遮断環境で通し、POST・JSON・TLS・リダイレクト禁止・通知先を確認する。Slack エラーでも通常メール成功が維持され、旧フォームへの引数・結果・エラー処理は変わらない。
- [x] AC-08: PHP 7.4.33 lint と対象機能の意味のある fixture が合格する。プラグイン本体、公開フォーム、旧テーマの変更はなく、本番資格情報なしで検証できる。
- [x] AC-09: 配布前にコード・差分・検証資料へ実 URL が含まれないことを確認し、本番対象ファイルと対象メタ、現在値のバックアップ、失敗時の戻し方を具体化する。今回の「旧テーマ側の設定を保持したまま、新テーマ用だけに追加する方針で進めて」というユーザーの明示承認の範囲で反映する。旧テーマへの影響や範囲の変更が判明した場合は、反映前に確認する。
- [x] AC-10: 明示された本番反映後も、今回の作業でテーマを切り替えず、PHP・プラグイン・旧フォームを変更しない。実際の Slack／メール送信試験は別の明示された手順として扱い、今回のローカル合格を実受信の確認と混同しない。

## 4. S1 と検証・反映の境界

1機能・1スプリント。Generator はテーマ内に機能を閉じ、既存 admin ファイルから専用ファイルを読み込む等、最小の差分とする。通常の共存無効時は追加 hook を登録しない。既存の全機能の広範な再設計・テスト追加は行わない。

まず隔離環境で架空 URL と合成入力を使用し、HTTP とメールを実行前から遮断する。AC-01〜08 を実プラグインと必要な限定 fixture で確認し、Evaluator が独立に旧フォームの不変・秘密非表示・保存対象を評価する。

主担当は最新の本番状態を確認してから、変更ファイルと新3件の対象メタを非公開に保存し、具体的差分・復旧方法を確認して、ユーザーが明示承認した新テーマ専用の範囲で反映する。2026-10-19の対象バックアップはPC保存・一致確認まで完了し、その直後にユーザーから追加バックアップは不要との指示を受けたため、追加取得は行わない。復旧は今回変更したファイルと対象メタに限定し、通常の問い合わせ等を失う全 DB 巻き戻しはしない。未有効の場合、管理 UI を確認する目的だけで本番テーマを切り替えず、隔離検証と承認済みの限定設定手段を分ける。

## 6. 実装・反映の結果（2026-10-19）

AC-01〜08は合成入力・外部通信を遮断した実プラグイン検証と独立評価で確認した。375px・1920pxの表示確認は、実描画結果を使う静的プレビューであり、本番の認証済み管理画面による保存操作や実通知の受信確認ではない。

AC-09〜10は16:50（日本時間）の限定反映で確認した。新テーマの2ファイルと新3フォームの通知メタだけを反映し、書き込み後に別接続で照合した。旧テーマは有効のまま、旧フォーム・通常メール・共有設定・PHP・プラグインを維持。作業専用SSH鍵は削除済み。追加バックアップ不要の指示後は追加取得していない。実際のテーマ切り替えとメール／Slack受信確認はユーザーが行う。

操作方法と確認範囲は `docs/production-slack-20261019.md` に記録した。
