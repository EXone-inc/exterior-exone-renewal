## 1. 背景・目的

- ヘッダーの「RECRUIT」・ドロワー / フッターの「採用情報」（`inc/menus.php` で `#`）と、TOP の RECRUIT セクションの「VIEW MORE」（`template-parts/top/section-recruit.php` で `#`）の行き先が無い。リニューアル後のサイトにも、現サイトと同じ採用ページと応募フォームを用意し、求職者が仕事内容・働く人・募集要項・待遇・選考フローを読んでそのまま応募できるようにする
- 見た目・文言・動きは現サイトを忠実に再現する（ヘッダー・フッターは新サイトのもの）。ただし外部ライブラリ（Three.js / Splide / Font Awesome）は使わず、テーマ内で完結させる（決定 §2-1）
- 応募は Contact Form 7（以下 CF7。ローカルは 6.1.5 導入済み）で受け、採用担当のアドレスへ現サイトと同じメールを送る。フォームの雛形はテーマのコードを正とし、本番にも同じ手順で登録できるようにする（お問い合わせ `inc/contact-forms.php` と同じ作法）
- 求人媒体などから張られている `/recruit/#sales` などの URL で、該当職種の募集要項が開いた状態になる互換を保つ

## 2. スコープ

### やること
- 固定ページ `recruit`（ID 105・作成済み）を `page-recruit.php`、その子ページ `entry`（ID 106・`/recruit/entry/`・作成済み）を `page-recruit-entry.php` で表示する

- 応募ボタンの固定表示（Training 以降、画面下中央）
- `/recruit/#<スラッグ>` で該当職種を開いてスクロール
- 応募フォーム: CF7「採用フォーム」をテーマのコードで登録する関数、現サイトと同じ項目・markup・メール設定、テーマの CSS での見た目、送信・完了・エラー表示
- 導線の接続: ヘッダー・ドロワー・フッターの RECRUIT / 採用情報、TOP の VIEW MORE を `/recruit/` に
- 決定 §3 の 6 点の修正（スライダーの重複除去・Challenge の綴り・モーダルの Q6 削除・執行役員の ※1 削除・末尾の Contact us を置かない・粒子の自前実装）

- SP（375）・中間幅の補間、`CLAUDE.md` のフレーム対応表への追記、回帰確認
- 公開前チェックリスト（§7）

### やらないこと（範囲外）
- 粒子の WebGL（Three.js）版、写真スライダーのドラッグ操作、職種ナビ（`#reqNav`）、確認画面、自動返信メール（メール (2)）、reCAPTCHA の導入（公開前チェックリストへ）（決定 §4「対象外」）
- 郵便番号からの住所自動入力（現サイトの markup に `p-postal-code` 等のクラスはあるが、自動入力のライブラリは読まれていない。クラスは残してよいが機能は付けない）

- 募集要項・インタビュー・FAQ を管理画面から編集できるようにすること（CPT・カスタムフィールドは作らない。文言はテーマのデータに持つ。オープン論点 Q12）

## 3. 機能一覧

> 検証幅: 主検証幅は **1920** と **375**。**768** は「破綻しない（横スクロール・はみ出し・重なり崩れが無い）」ことだけを見る。S1〜S3 は 1920 を主に、375 の細部の受け入れは S4（F-12）でまとめて行う（S1〜S3 でも 375 で横スクロールが出ないことだけは確認する）。
> **「忠実再現」の照合**: カンプが無いので、(1) 参照物の HTML / CSS の値（文言・構成・配色・寸法）と、(2) 現サイトのスクリーンショット（Evaluator が https://exterior-exone.com/recruit/ ・ `/recruit/entry/` を**同じ幅**（1920×1080 / 375×812）で撮り、新サイトと並べて見比べる）で判定する。一致必須はセクション構成・配置・配色・タイポグラフィ・余白感、**px の完全一致は求めない**（CLAUDE.md「忠実再現」の定義）。ヘッダー・フッター・現サイト末尾の Contact us は比較対象外。現サイトのブレイクポイントは 960 なので、1920 と 375 ではどちらも同じ側（PC / SP）の見た目になる。
> **ブレイクポイント**: 現サイトの `min-width: 960px` の指定は **1025px 以上（PC）** に、`max-width: 959.98px` は **1024px 以下（SP）** に読み替える。768・1100・1200・1920 の指定はそのまま残す（決定 §2-3）。
> **値の読み替え**: rem は 1rem = 10px。`clamp()` の vw 指定はそのまま使ってよい（1920 / 375 で現サイトと同じ大きさになる）。比例ブロック（`--*-vu`）は使わない（決定 §4）。色・寸法は `css/recruit.css`（フォームは `css/recruit-entry.css`）の `:root` に `--rc-*` トークンとして定義してから使い、直値を散らさない（CLAUDE.md・決定 §2-2）。
> URL のホストは `http://exterior-exone-renewal.local`。以下では省略して `/recruit/` のように書く。
> **検証用の目印**（クラス名は Generator が決めてよいが、以下の属性は必ず付ける）:
> - セクション: `[data-section="recruit-fv"|"recruit-training"|"recruit-work"|"recruit-marquee"|"recruit-requirements"|"recruit-benefits"|"recruit-flow"|"recruit-faq"]`、応募フォーム `[data-section="recruit-entry"]`
> - 粒子: `canvas[data-recruit-particles]`（値 = 粒子の数）。FV の写真スライダーの列 `[data-recruit-slider]`、流れる大文字の列 `[data-recruit-marquee]`
> - 応募ボタン: FV 内 `[data-recruit-apply="fv"]`、固定表示 `[data-recruit-apply="fixed"]`
> - Work: カードの開くボタン `button[data-recruit-modal-open="<1|2|3>"]`、モーダル `[data-recruit-modal="<1|2|3>"]`、閉じるボタン `[data-recruit-modal-close]`
> - 募集要項: 職種 `[data-recruit-job="<slug>"]`（要素の `id` も `<slug>`）。見出し（開閉ボタン）は `aria-expanded` を持つ
> - FAQ: 質問ボタン `button[data-recruit-faq]`（`aria-expanded` を持つ）
> **命名の衝突に注意**: TOP の RECRUIT セクションが `.p-recruit*`（`style.css`）を使っている。採用ページのクラスは `.p-recruit` で始めない（例 `.p-rc*`）。トークンは `--rc-*`（決定 §2-2。現時点でテーマ内に `--rc-` は無い）。

### F-02: FV（粒子 Canvas・写真スライダー・コピー・応募ボタン・下端のカーブ）

- 概要: 白地の上に色とりどりの小さな点が奥から手前へ流れる粒子アニメーション（Canvas 2D の自前実装）を FV 全面に敷き、その上に社員写真のスライダー（右→左へ流れ続ける）、コピー（英字・和文・サブ）、黒い丸ボタン「応募する」、下端のカーブを重ねる
- Figma ノード: —（現サイト `.recruit-first--view`・`#mycanvas`・`.recruit_slide`・`.text-container`・`.rec-rink_btn`・`.clipped-rounded`、`recruit.js` 冒頭の Three.js 部分と `splide_re`）
- ユーザーストーリー: 求職者として、ページを開いた瞬間に会社の雰囲気と働く人の顔を見たい。なぜなら、最初の印象で読み進めるかどうかを決めるから。
- 含むもの:
  - **粒子**（現サイト recruit.js の Three.js 実装を Canvas 2D で再現する。見た目の基準）:
    - 地は白（#fff）。FV 全面（幅・高さとも FV と同じ）に敷き、写真・コピー・ボタンより背面
    - 粒子 140 個。色は 6 色 `#006e54 / #0075c2 / #009b9f / #fdd35c / #ea5532 / #915da3` からランダム、不透明の丸い点
    - 奥から手前へ流れる（遠近: 奥ほど小さく画面中心寄り、手前に来るほど大きく外側へ広がる）。現サイトの点の見た目の大きさ（手前で数 px 程度の小さな点）に合わせる
    - 速さ: 読み込みから最初の 2 秒は速く（現サイトの 1 フレームあたり 0.13）、ease-out で減速し、2 秒以降はゆっくり（0.005）一定。カメラ位置を越えた点・画面外に出た点は奥へ置き直し、色も選び直す（点が尽きない）
    - リサイズで FV の大きさに追従する（引き伸ばしでぼやけない。高解像度画面でも点がにじまない）
    - `prefers-reduced-motion: reduce` では動かさず、点を散らした 1 枚の静止画を描く
    - FV が画面外にある間は描画を止めてよい（CPU 節約。オープン論点 Q1）
  - **写真スライダー**: 社員・店舗の写真 7 枚（決定 §3-1 で重複を除く。並びは現サイトの順から 2 枚目以外の `m-222079_photo1…` 重複分を除いたもの = `EXONE_社員紹介-2` / `m-222079_photo1-1-…640x480-1` / `EXONE_社員紹介-15` / `EXONE_42` / `EXONE_社員紹介-9` / `EXONE_社員紹介-10` / `青森内観-ロゴ`）を右→左へ途切れずに流し続ける（既存の `js/plans-imglist.js` の仕組み。ドラッグ・ホバーでの停止は無し）。写真は角丸 20・影 `0 5px 15px rgba(0,0,0,.741)`・cover。大きさと間隔は 3 段: **1024 以下 180×250・間隔 40 / 1025〜1919 230×300・間隔 35 / 1920 以上 280×350・間隔 50**。速さは現サイトの AutoScroll speed 1 ≒ **60px/秒**（幅によらず同じ見た目の速さ。オープン論点 Q2）。`prefers-reduced-motion: reduce` では止まった並び
  - **コピー**（決定 §4: 現サイトの「h1 の中に p」を直す。構造はオープン論点 Q3 の既定）: 白の半透明（#ffffffcf）の帯の上に中央揃えで
    - 英字「Creative × Challenge」: `clamp(24px, 15.92px + 3.01vw, 52px)`・weight 900・影 `3px 3px 5px rgba(0,0,0,.3)`
    - 和文「私たちと共に新たな / エクステリア業界を創造しよう！」（2 行）: `clamp(22px, 14.5px + 2.79vw, 48px)`・700・同じ影
    - サブ「エクステリア業界の古い構造を見直し / 新たな時代を創る仲間を募集中！ / 業界の変革を実現するため、共に挑戦しましょう。」（3 行）: 上 40・`clamp(18px, 15.67px + 1.17vw, 25px)`・500・lh 1.8・影 `2px 2px 4px rgba(0,0,0,.2)`
    - 帯: SP は全幅（左右 14・下 14 の内余白、上 50）、PC は最大 1060 幅で中央（上 20・下 20）
  - **応募ボタン**「応募する」（`[data-recruit-apply="fv"]`、href `/recruit/entry/`。支店モードでは `exterior_exone_store_link()` を通す）: 幅 280・黒地（#000）・角丸 45・上下 28 の内余白・白文字 15px 700・影 `0 0 5px #000`・右寄りに右向き矢印アイコン（白）。上下 60 の外余白で中央。**ホバー**: 左上から白い円が広がって地が白になり、文字が黒、矢印が「丸の中の右矢印」に替わって黒（0.5 秒。現サイト `.rec-btn-flat:before` / `.rec-btn-border::after`）
  - **下端のカーブ**: FV の下端に #f9f9f9 の帯を重ね、上辺を弧で切り抜く（中央が下に膨らむ白い FV の縁に見える）。SP は浅いカーブ（現サイト `roundedClipMobile`。高さ約 100・FV 下端から 50 はみ出す）、PC は深いカーブ（`roundedClipPC`。高さ約 200・FV 下端から 10 はみ出す）。FV の下余白は SP 100 / PC 50
  - 1025 以上の FV の地は #000（現サイトどおり。粒子 Canvas が白で覆うので見た目は白）
- 受け入れ基準:

## 6. オープン論点（Planner が判断できなかったこと。括弧内の既定で実装し、Generator は**勝手に変えず報告に含める**。呼び出し側でユーザーに確認する）

- Q1（要確認・アニメーション）: 粒子の密度・速さ・点の大きさの見え方。Canvas 2D は Three.js の透視投影と同じ式で再現できるが、点の大きさ（手前で何 px か）や画面の端への広がりが現サイトとずれることがある。**既定: 現サイトのカメラ（画角 75°・奥行き 0〜10・カメラ位置 3）と同じ遠近で描き、点の大きさは現サイトの 1920 / 375 のスクリーンショットに見た目で合わせる**。Generator は現サイトと並べた連続スクリーンショット（または短い動画）を報告に付ける。あわせて「FV が画面外のときは描画を止める」（CPU 節約。見た目は変わらない）を既定で入れる
- Q2（要確認・アニメーション）: 写真スライダー・流れる大文字の速さ。現サイトは「1 フレームあたり px」なので画面のリフレッシュレートで速さが変わる（120Hz の画面では倍速）。**既定: 60Hz 相当の px/秒に固定（写真 60px/秒、大文字 SP 84px/秒・PC 48px/秒）**。代案: 画面幅あたりの時間で揃える（既存 PLANS の方式）
- Q3（要確認・構造の直し方。決定 §4「h1 + p に直す」）: FV のコピーの見出しの構造。**既定: `h1` に「Creative × Challenge」と「私たちと共に新たなエクステリア業界を創造しよう！」の 2 段を入れ（見た目は現サイトの 2 段のまま）、サブの 3 行を `p` にする**。代案: (b) `h1` は和文コピーだけ、英字は装飾の `p` / (c) `h1` は英字だけ。あわせて各セクションの見出し（現サイトは `h2` の中に `p`、または `div` + `p`）は **`h2`（英字 + 和文を 1 つの見出しに。英字は装飾として読み上げてもよい）** に揃える。募集要項の注記が `ul` の直下にある不正な入れ子なども、見た目を変えずに正しい構造に直す
- Q4（要確認・アニメーション）: モーダルの開閉のアニメ。現サイトはパネルが 0.8 秒でフェードイン、閉じるときはアニメなしで消える（「右から出る」のはパネルの位置が右寄せという意味で、横にスライドはしない）。**既定: 現サイトどおり 0.8 秒のフェードイン・閉じるときは即時**。代案: 0.3 秒のフェード / 右からスライド
- Q5（カンプに無い挙動・既存方式との差）: モーダルの暗幕クリックで閉じるか。現サイトは暗幕もモーダルの一部なので、暗幕を押しても閉じない（× と Esc だけ）。**既定: 新サイトの見積モーダルと同じく暗幕クリックでも閉じる**（決定 §2-6「既存モーダルの方式」）。代案: 現サイトどおり閉じない
- Q6（重なり順）: 固定の応募ボタンとヘッダー・ドロワー・モーダルの重なり。現サイトは最前面（z-index 99999）で、モーダルを開いても暗幕の上に出る。**既定: モーダル・ドロワーを開いている間は固定ボタンを隠す（暗幕の上に出さない）。それ以外は最前面**。代案: 現サイトどおり常に最前面
- Q7（カンプに無い状態）: ヘッダーを重ねたときの FV の上余白。現サイトはヘッダーが FV の外にあり、写真スライダーの上 60。**既定: ヘッダーの高さ + 60 をスライダーの上に空ける**（粒子の白地はヘッダーの下まで）。応募フォームは見出しの上 100 にヘッダーの高さを足す（コラムと同じ）
- Q8（構造の直し方）: 応募フォームの雛形の不正な入れ子（`label` の中に `p`、お名前の `<p>` の閉じ忘れ、`label` が入力と結び付いていない）。**既定: 閉じ忘れは直す。`label` 内の `p` は `span` に替える（クラス名・見た目は同じ）。ラベルと入力の結び付け（`for` / CF7 の `use_label_element`）は現サイトどおり付けない**。代案: 現サイトの markup を一字一句そのまま
- Q9（要確認・決定と参照物の食い違い）: 送信ボタンの文言。決定 §2 末尾は「応募する」、現サイトのレンダリング結果（`prod-entry-body.html`）は `value="送信する"`。**既定: 決定が正なので「応募する」**。現サイトどおり「送信する」にするかを確認
- Q10（文言の直し方）: 営業責任者（執行役員）の文言に含まれる CJK 互換部首の文字（`⻑` `⾶` `⽴` `⼊` `⾏` `⽰` `⽅` `⼤` `⾦` `⽤` `⼈` `⽇` `⾃` `⼠` 等。PDF からのコピーの名残）。**既定: 見た目が同じ通常の漢字（長・飛・立・入・行・示・方・大・金・用・人・日・自・士 等）に置き換える**（検索・読み上げで正しく扱われるため）。代案: 原文のまま
- Q11（JS 無効時）: 募集要項・FAQ の JS 無効時。**既定: 募集要項 6 職種とも開いた状態、FAQ も回答を開いた状態で表示。モーダルは開けない（カードの＋ボタンは出さない、または押しても何も起きない）**。代案: モーダルの中身をカードの下に展開して表示
- Q12（運用）: 募集要項・インタビュー・FAQ の更新方法。現サイトは固定ページの HTML を直接編集していた。**既定: 今回はテーマのデータ（`inc/recruit-data.php`）に持ち、更新はテーマの修正で行う**。代案: 職種を CPT にして管理画面から編集（別スプリント・別仕様書）
- Q13（要確認・CF7 の表示）: 完了・エラーのメッセージの文言と出し方。**既定: 文言は CF7 標準の日本語（完了「ありがとうございます。メッセージは送信されました。」、入力エラー「入力内容に問題があります。確認して再度お試しください。」等。現サイトも標準のままと推定）。完了メッセージは CF7 の標準どおり送信ボタンの下に出し、フォームは CF7 が空に戻す（フォームは隠さない）。入力エラーのときのフォーム全体の帯メッセージは出さず、項目下の文言だけ（お問い合わせ Q11 と同じ）**。代案: お問い合わせのようにフォームを隠して完了文だけ出す / 現サイトの完了文面を管理画面から確認して合わせる
- Q14（カンプに無い状態）: CF7 が無効・フォーム未登録のときの案内文。**既定:「ただいま応募フォームを準備中です。お手数ですが、recruit@exone-exterior.jp までメールでご応募ください。」**
- Q15（ブレイクポイントの読み替えの差）: 現サイトの 960〜1024 は PC の見た目だったが、新サイトでは SP の見た目になる（Work のカードの列が横スクロール、Flow が縦積み 等）。また Benefits のカードは 768〜1099 で 2 列・1100 以上で 4 列のまま（1025〜1099 は PC の組みの中で 2 列）、Flow の「1025〜1199 は間隔を詰める」も現サイトの 960〜1199 から読み替え。**既定: 機械的に読み替え、961〜1024 と 1025〜1099 のスクリーンショットを報告に付ける**
