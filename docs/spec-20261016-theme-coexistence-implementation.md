## 1. 確定する構成

### 新用データは非公開の保存領域へ分離する

新用の施工事例・お知らせ・固定ページを `exr_works`・`exr_news`・`exr_page`、分類を `exr_works_category`・`exr_works_package`・`exr_works_tag` として分離する。既存 `works`・`news`・`page` の内容や登録を変更しない。

新用の投稿タイプ・分類は公開 URL、REST、通常検索、RSS、サイトマップに自動参加しない保存用の領域とする。さらに、新用レコードには非公開の保存状態（例 `exr_stored`）を使い、元の publish / draft 等は専用メタに保持する。**新用レコードを publish で保存し、新テーマだけが目印で絞る方式は採用しない。** 旧テーマの通常の公開投稿検索からも出ない状態で、新テーマのアダプターだけが元状態・日時・対象データ群を確認して明示的に取得する。

新フォーム・添付も独立したレコードとし、旧テーマの公開 REST・添付ページ・サイトマップ等への混入を防げる保存状態を用いる。CF7 と画像表示がその状態で動くことを隔離環境で実測する。標準の公開状態へ変更して試験を通すだけの解決はしない。

### 公開 URL と表示は新テーマが有効なリクエストだけで解決する

新テーマ内のアダプターが、公開パスを新用データと既存テンプレートへ対応させる。非公開保存用 CPT 自体に公開アーカイブや恒久的な rewrite を持たせない。新テーマを外すと URL 振り分け・専用リンク処理・新用表示は働かなくなる。

既存固定ページは本文・スラッグ・親子関係・テンプレート指定を変更しない。TOP の表示差も `show_on_front`・`page_on_front` の保存値を変えずに実現する。`/column/` の固定ページ ID 3474、`/works/` の ID 2953 を残す。

共有コラムは本番由来の `column` と階層ありの `column_category` をそのまま使う。本番の CPT UI と Custom Post Type Permalinks の定義を優先し、ローカルの重複登録やアーカイブ設定を持ち込まない。コラム本文・メタ・画像参照は保存せず、新デザインで読む。

### 共有設定を書き換えない範囲

テーマ・インポーター独自の処理で home / siteurl / フロントページ / パーマリンク / 公開設定 / CPT UI / プラグイン / メニュー / 旧テーマ設定を保存し直さない。通常表示・テーマ有効化で自動インポート、フォーム登録、データ更新を行わない。

WordPress 標準のテーマ選択自体は `template`・`stylesheet` 等を更新し、`check_theme_switched()` は rewrite を再生成する。この標準動作を「DB 変更 0」とは報告しない。標準のテーマ選択と一時状態の差を別記し、サイト固有の保護対象設定が変わらず、旧テーマへ戻したとき既存 URL の解決が元どおりになることを検証する。新テーマ独自の強制 flush と共有設定の付け替えは不要にする。

## 2. 作業場所・入力・実装の分担

### 作業場所

非公開の `migration-private/` 配下に新しい隔離サイト、専用 DB、runtime、ログ、証跡を用意する。既存 Local 3 サイト、元 uploads、既存 staging、本番の未有効テーマを上書きしない。PHP は実際の 7.4.33 を用いる。

初回 WordPress 起動より前に、本番 DB 接続・外部メール・Webhook・cron・外向き通信を遮断する。隔離用接続・管理者情報を用い、本番資格情報を外部へ使わない。ブラウザからの外部通信も別に制限する。サイトは loopback にのみ公開し、取得原本・実データ・資格情報は Web 公開領域の外に置く。

復元した旧サイトは、隔離のための URL・資格情報・送信遮断を設定した後に比較基準を採る。その後の新用データ取り込み・テーマ切り替えが、基準の旧レコードを変更しないことを測定する。共有コラムの本文中にある本番 URL の表示確認は、保存本文を変えず隔離内で解決する。

## 3. インポーターのデータ契約

- 実行先は専用 private root、識別ファイル、ソケット、DB 名、prefix、home/siteurl の組み合わせがすべて隔離環境と一致する場合だけ。`.local` や引数名だけの判定は不可。本番・元 Local・任意接続先・識別不一致は書き込み前に拒否する。
- SQL store は必要な既存テーブルへのパラメータ化した読み書きだけを扱い、利用者から任意 SQL を受け取らない。WordPress や CF7 を起動して登録・更新フックを呼ぶ方式にしない。DB・テーブルの準備は環境担当の別工程とし、インポーターは保護対象 options や旧レコードを変更しない。
- `source_key` とデータ群識別で新用項目を特定する。同一内容ハッシュなら再利用し、同じ識別で異なる内容・複数候補は停止する。元 ID、タイトル、スラッグだけで既存レコードを再利用しない。
- 旧レコードを update / delete しない。変更可能なのは今回の新用レコードと、その取り込みで作ったファイル・対応情報だけ。失敗時の復旧対象もこれらに限定し、旧 DB 全体を戻さない。
- 分類の親子、投稿の親、添付、フォームを新 ID へ対応させ、すべての参照を付け替える。対応表と作成記録は非公開に残す。段階ごとに失敗を再現し、途中状態が公開されず、再実行で重複しないことを確認する。
- 新用の本文・メタだけを、記録済み参照に沿って変換する。画像 4 枠、旧ギャラリー順、アイキャッチ、添付メタ、HTML/srcset、ブロック、数値フォーム ID、親ページ、分類を扱う。単純な全体文字列置換で ID・URL・シリアライズを壊さない。
- コラム投稿・本文・分類、旧ページ、旧フォーム、旧添付、ユーザー、options、コメント、受信履歴を取り込まない。新用のコメント・ping は closed、コメント数は 0。
- 除外コラム等を元親とする添付は、元親を出典として残し、追加先 parent は 0 とする。本番の同じ数値 ID と結びつけない。添付 38 件を未参照という理由で除外しない。
- メディアは新規専用ディレクトリへ追加し、同名の旧ファイルを置き換えない。元画像・派生サイズの内容ハッシュを照合する。画像 URL 自体の直接配信と、旧サイトの検索・REST・添付ページ等への掲載を区別して検証する。
- CF7 の新用選択は `_exr_source_key` と `_exr_form_role` 等の専用識別だけを使う。旧 role メタの流用・タイトル検索へのフォールバック・既存フォームへの識別メタ追加は禁止。元のフォーム `_hash` を再利用しない。旧フォームの設定は変更しない。
- 取り込み完了と参照検証が済むまで、新用データ群を表示可能にしない。新テーマで必要データがない場合も、無言で旧施工事例やローカル仮コラムを混ぜない。管理者へ不足を示し、公開側は未完成データを出さない。

## 4. 表示面と互換性の要件

| 表示面 | 新テーマ選択中 | 旧テーマへの復帰後 |
|---|---|---|
| TOP | 既存 front-page の新デザインとローカル由来の新用データ | 旧 TOP と旧内容 |
| 施工事例・お知らせ | 専用データだけ。件数・年月・分類・関連・前後リンクも分離 | 既存一覧・個別・検索・分類のまま |
| 固定ページ・店舗 | 元の親子と新テンプレートを保持。既存ページは変更しない | 旧固定ページ・テンプレート・既存 URL のまま |
| サンクスページ | `/contact/thanks/` と `/recruit/thanks/` を別の親として解決。noindex・sitemap 除外 | 新用ページが旧検索・sitemap に現れない |
| コラム | 本番の同じ 18 記事と階層分類。保存値を変更せず新デザイン | 同じ記事を旧デザイン・旧 URL・旧 SEO 出力で表示 |
| 問い合わせ・採用 | 専用フォーム ID・役割を使い、新用デザインで動く | 旧フォーム・旧送信設定のまま |

本番の既存 URL を優先して維持する。店舗の `/store/store-aomori/` 等とローカル `/store/aomori/` 等の差は、公開パス・canonical・別名パスの対応表を作り、新テーマ内だけで扱う。共有 Redirection 設定や旧ページのスラッグを変えない。確認せずに全 URL を TOP へ転送しない。

コラム一覧は本番固定ページ `/column/` を保ち、ページ送りとカテゴリー絞り込みも新デザインで解決する。コラムの投稿タイプを二重登録せず、階層分類を階層なしへ変えない。新テーマの `get_post_type_archive_link()`、`is_post_type_archive()` 等のローカル専用前提はアダプターで見直す。

AFFINGER 由来の title / description / robots / canonical / OGP / 構造化データ、ブロック・ショートコードを実データで確認する。必要な互換処理は新テーマ側の読取・表示処理に限る。既存コラムの保存本文から style や script を削除せず、表示処理後も本文・目次・表・画像・FAQ・著者情報が欠落しないことを確認する。
