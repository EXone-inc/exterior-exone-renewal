## 1. 背景・目的

- メニューの「コラム」（ハンバーガーメニュー・フッター。支店モードも）は行き先が `#` のまま。現サイト `exterior-exone.com/column/` にある外構のお役立ちコラムを、新サイトの見た目（白地・新しい書体・余白）で一覧と詳細として用意する
- 記事は担当者が WordPress 管理画面（ブロックエディタ）で書く。現サイトの記事は WordPress の書き出し／取り込みでそのまま移せるよう、投稿タイプ・タクソノミーの名前と本文内の部品のクラス名を現サイトと同じにする
- コラムの中身は後から入れるため、今回は仮データ（現サイトのタイトル 10 件 + 仮 2 件、うち 1 件は現サイトのカーポート記事の本文）で作る
- 支店ページ・WORKS ページの COLUMN セクションは、いまお知らせ（`news`）を仮に出している。これをコラムの最新記事に差し替える

## 2. スコープ

### やること
- 投稿タイプ `column`・タクソノミー `column_category` の登録（テーマのコード）
- ローカルの仮データ投入（WP-CLI。カテゴリー 5 つ・記事 12 件・アイキャッチ）
- 一覧 `/column/`（`archive-column.php`）: 見出し・カテゴリーの絞り込み（サーバー側）・記事カード 10 件/ページ・ページ送り・0 件表示
- 詳細 `/column/<slug>/`（`single-column.php`）: カテゴリー・日付・タイトル・アイキャッチ・本文・前後の記事・一覧へ戻る・末尾の COLUMN セクション
- 本文の基本スタイル（見出し・段落・画像・リスト・表）と、本文内の部品（現サイトと同じクラス名）のスタイル。配色は指示書きの反転ルール
- メニューの「コラム」を `/column/` に接続（支店モードは `?store=` 付き）
- 共通 COLUMN セクション（支店・WORKS・コラム詳細の末尾）の中身をコラムの最新 3 件に差し替え
- PC（1920）・SP（375）。768 は破綻しないこと
- `CLAUDE.md` のフレーム対応表に COLUMN 行を追記

### やらないこと（範囲外）
- 詳細ページのパンくず（決定 §2）
- タブレット専用の組み（1024 / 1025 の切り替えのみ）、記事の検索、タグ、著者ページ、SNS シェアボタン
- 関連記事（末尾の COLUMN セクションで代える）
- カテゴリーごとのアーカイブページ（タクソノミーの個別 URL）のデザイン。どこからもリンクしない
- 支店モードによる記事の絞り込み（`?store=` はヘッダー・フッターの出し分けとリンクの引き継ぎだけ。決定 §2）
- 現サイトからの記事の実移行（手順は §7 公開前チェックリストに書く）。本文内の画像は現サイトの URL のまま（仮記事のみ）
- TOP の NEWS セクション（`template-parts/top/section-news.php`）と `exterior_exone_news_cards()` の変更（TOP はお知らせのまま）
- 「お知らせ」メニューの行き先（`#` のまま）
- 画像の最終調達。仮データのアイキャッチはテーマ内の WORKS 写真（AI 生成の**差し替え前提の仮画像**）

## 3. 機能一覧

> 検証幅: 主検証幅は **1920** と **375**。**768** は「破綻しない（横スクロール・はみ出し・重なり崩れが無い）」ことだけを見る。S1・S2 は PC を主に、SP の最終受け入れは S3（S1・S2 でも 375 で横スクロールが出ないことは確認する）。
> 「忠実再現」の判定対象は **Figma の指示書き（配色・幅 1600 / 1400・文字サイズとフォントの統一）と現サイトの構成要素**。px の一致は求めない。寸法の目安は現サイトの CSS（`column.css` / `column_detail.css`。1rem = 10px）と `prod-list.html` の並び。
> 配色の反転ルール（指示書き `875:47`。以下「反転ルール」）: 背景 → white4 `#f3f3f4` / 見出し・強調 → black2 `#1a1a1a` / テキスト → black1 `#4d4d4d` / オレンジのアクセント（現サイトの金 `#c79a5f`）→ orange1 `#d2832f` / 日付などのサブテキストと線 → gray2 `#d9d9d9`。色はすべて既存トークン（`--color-white4` / `--color-black2` / `--color-black1` / `--color-orange1` / `--color-gray2`、白系の面は `--color-white1`〜`--color-white3`）を参照し、直値を散らさない。
> 以下の AC の記事・カテゴリーは §4「仮データ」の表に従う（S1 で投入）。URL の `<外構全般>` などは**タームのスラッグ（URL エンコード済み）**を指す。

### F-03: 一覧の絞り込み（`?cat=`）とページ送り

- 概要: タブを押すとサーバー側でそのカテゴリーの記事だけを表示する（現サイトと同じ `?cat=<スラッグ>`）。10 件を超えるとページ送り（前へ・番号・次へ）を出し、2 ページ目以降は `/column/page/<N>/`（絞り込み中は `?cat=` を引き継ぐ）
- Figma ノード: タブ列 `875:43`（参考画像）
- ユーザーストーリー: 来訪者として、自分の地域や知りたいテーマのコラムだけを見たい。なぜなら、関係のない記事を読み飛ばす手間を省きたいから。
- 含むもの:
  - クエリ変数は `cat`（現サイトと同じ）。`cat` は WordPress 予約のクエリ変数なので、衝突（無視される・リダイレクトされる・カテゴリー扱いされる等）があれば `column_cat` に変えてよい。その場合は現サイトからの URL 互換は不要で、**変えたことと理由を報告する**（§6 Q4）。以下の AC の `?cat=` は、変えた場合は読み替える
  - 存在しないスラッグ（`?cat=unknown`）は「すべて」と同じ表示（§6 Q5）

## 6. オープン論点（Generator は括弧内の既定で進め、変えた点・気づいた点を報告する。呼び出し側がまとめてユーザーに確認する）

- Q1（**決定からの変更・要確認**）: 決定は一覧・詳細の CSS を `css/column.css` としているが、**同名のファイルが既に共通 COLUMN セクション（`.p-scolumn`・`.c-store-*`・`--st-*`）の CSS として存在する**（ハンドル `exterior-exone-column`。支店・WORKS で読み込み中）。**既定: 新規ファイルは `css/column-page.css`（ハンドル `exterior-exone-column-page`）にし、既存の `css/column.css` は名前・中身とも変えない**。代案: 既存を `css/section-column.css` 等に改名して `css/column.css` をコラムページ用にする（支店・WORKS の読み込みも変わるので回帰範囲が広がる）
- Q2（指示書きの解釈）: 「コンテンツ幅 1600・コンテンツ内の幅 1400」の割り当て。**既定: 1600 = 左右 160 の外枠、その内側 1400 にタブ・カード・ページ送り・詳細の記事（タイトル〜本文〜前後の記事）をすべて置く（見出しは中央揃え）**。代案: タブの線とページ送りだけ 1600、カードと本文が 1400。なお本文 1400 は 18px で 1 行 約 75 文字と長め（読みやすさを優先して本文だけ狭める案もある）
- Q3（文字サイズの具体値。指示書き「別ページと統一、もしくは近いサイズで読みやすい範囲」）: **既定: COLUMN 76/48（`--fs-display-lg`）、和文サブ 20/14（`--fs-copy-md`）、本文 18/14（PC は `--fs-body` と同じ。SP は `--fs-body` の 12 では長文が読みにくいので 14）、記事タイトル h1 40/20、本文 h2 28/18・h3 22/16、カードのタイトル 24/16、抜粋 16/13、タブ 18/14、日付 14/11**（PC / SP）
- Q4（予約語）: `?cat=` は WordPress 予約のクエリ変数。**既定: まず `cat` で実装し、メインクエリ・リダイレクト・カテゴリー判定に干渉が出たら `column_cat` に変えて報告**（その場合は現サイトの `?cat=` からの互換は不要。決定 §3）
