# Spec: S3 準備版 — ローカル専用の読取エクスポート・パッケージ検証・オフライン照合

- 作成日: 2026-10-15
- 親仕様: `docs/spec-20261015-theme-coexistence.md` の F-03 / S3。
- 対象段階: **S3 の準備部分だけ。本番への取り込み機能、WordPress への書き込み、新テーマの表示切り替えは含めない。**
- 最新のユーザー指示: バックアップ完了まで時間がかかるため、完了待ちをいったん飛ばして進める。これは本番変更やバックアップなしの本番適用を許可する指示とは扱わない。実行中の取得処理を停止・削除する操作も今回には含めない。
- 今回確定する方式: **WordPress を起動せずに既知のローカル DB を読み取り、新用データの論理的な識別情報を付けた非公開パッケージを作る。パッケージ単独の検証と、ファイルだけを使う取り込み前の模擬照合までを完成させる。**
- デザイン元: 該当なし。管理画面・公開画面の UI やデザインを変更しないため、Figma 取得・Playwright・ブラウザ操作は不要。
- 状態: 実装・実データ取得・検証を実施。結果と未適用範囲は §11 に記録する。親 S3 全体・本番移行の完了を意味しない。

## 1. この段階の目的と完了の意味

本番の複製がまだなくても、ローカルから「何を持ち出すか」「何を除外するか」「どの画像・分類・親ページ・フォームを参照しているか」を確定し、不完全なデータや重複を取り込み前に発見できる状態にする。

出力は将来の移行に使う**準備資料とデータ**であり、インストーラーではない。ツールに本番接続、取り込み、更新、削除、テーマ有効化、フォーム登録の機能を持たせない。適用フラグで解除できる隠れた実行経路も設けない。

この段階で「合格」と言えるのは、読取専用の抽出、データ形式、参照関係、除外条件、模擬照合の結果である。本番の既存記事が保護されること、新旧テーマの表示が切り替わること、実際の再取り込みが安全であることは、親仕様の隔離復元・取り込み・切り替え検証まで未確認のままとする。

## 2. 変更範囲と安全な保存場所

### 実装する場所

新規ディレクトリ `wp-content/themes/exterior-exone/tools/coexistence/` の中だけに、以下の責務を持つ CLI 用のソース、定義、合成テストを追加する。具体的な言語とファイル分割は Generator が決めるが、既存 PHP を実行してデータを得る方式は使わない。

Local PHP 8.2.29 の mysqli・zip・hash が利用可能と確認されているため、WordPress を起動しない PHP CLI を利用できる。**3 コマンドの責務と受入条件を固定し、コマンド名・ファイル名・スキーマの細かいフィールド名は実装担当の決定を尊重する。** 下記の名前は説明用であり、同等の契約を満たす実装へ改名を強制しない。

| 実装対象 | 責務 |
|---|---|
| 読取エクスポート CLI | 既知のローカル DB だけから対象データを取り出し、非公開パッケージを作る |
| パッケージ検証 CLI | DB に接続せず、形式・ハッシュ・参照・除外条件・パスを検査する |
| オフライン模擬照合 CLI | パッケージと対象環境の棚卸しファイルだけを入力にし、想定される衝突と未確認事項を出す |
| スキーマ・許可項目定義 | 入出力の形式、対象タイプ、許可するメタ、名前の対応、終了状態を固定する |
| 合成テスト・操作説明 | 壊れた入力や衝突を検出できること、DB 書き込み機能がないことを確認する |

- `functions.php`、`style.css`、`inc/`、テンプレート、既存 CLI、既存仕様書を編集しない。テーマから新ツールを読み込まない。
- 新ディレクトリは、将来の公開テーマ ZIP から除外する開発用ツールである。HTTP から実行される PHP の入口を設けず、PHP ファイルを使う場合も CLI 以外ではデータ処理前に終了する。
- ツールのソースと合成テストには実データ、本文のコピー、宛先、資格情報を入れない。
- 今回実際に作成する仕様書は本ファイルだけ。上記の実装ファイルは次の Generator の対象であり、Planner は作成しない。

## 4. 移行パッケージの仕様

### ファイル構成と責務

形式は UTF-8 の JSON を基本とし、実行可能な SQL・PHP・シェルや、PHP を起動するインストーラーを含めない。シリアライズ済みの値を含む場合もデータとして扱う。

| ファイル | 必須の内容 |
|---|---|
| `manifest.json` | 形式の版、ツールの版、実行 ID、作成日時、出典サイト識別、内容の識別値、対象・除外種別、件数、ファイル一覧・ハッシュ、完成状態、準備専用であること |
| `content.json` | 対象投稿・固定ページ、分類・関係、許可されたメタ。保存された本文と状態を維持する |
| `forms.private.json` | 対象 CF7 フォーム 3 役割の定義と許可された設定。宛先やメール文面が入るため非公開扱い |
| `media.json` | ローカル添付全件のデータ payload、元ファイル・派生画像の参照、利用関係、同梱ファイルの保存先・サイズ・ハッシュ |
| メディアファイル領域 | 全添付の実体。元画像と添付メタデータに記録された派生画像・元画像を安全な相対パスで同梱する。配置名は実装担当が決める |
| `references.json` | 親子、分類、画像、本文 URL、ショートコード、フォーム等の参照対応と未解決事項 |
| `validation.json` | 検査項目別の合否、件数、エラーコード、対象の論理識別子。本文・宛先・資格情報を含まない |
| `dry-run.json` | 対象棚卸しファイルの出典・完全性、想定する新規作成・再利用・衝突・保留の一覧。DB 実行計画ではない |
| `summary.txt` | 人が確認する短い件数・除外・警告・未検証範囲・次段階の説明。機密値を出さない |

- **ローカル添付 38 件すべての添付データと実ファイルを payload に同梱する。** コラムだけで使う添付や未参照添付を、未承認で除外しない。原本を読み取り、元画像・メタデータに記録された派生画像・元画像を非公開出力先へコピーする。コピー前後のサイズ・ハッシュで一致と取得中の変更を検証し、後からローカル画像が変わっても、この実行時点の画像をパッケージから再利用できる状態にする。元 uploads は変更しない。
- 元サイトのローカル URL は出典や生の本文に残り得る。新 URL へ一括置換せず、置換・保持の候補を `references.json` に分けて記録する。元データを改変しない。
- 同じ論理データなら、実行日時・実行 ID を除いた内容のハッシュが一致する。並びは論理識別子等で安定させ、DB の偶然の返却順に依存しない。
- ハッシュは破損や差分の検出用であり、出力を公開してよいという判断材料にはしない。

### 保存先の名前と論理識別子

この表は将来の移行先の名前を決めるもの。今回、投稿タイプ・タクソノミーの登録やレコード作成は一切しない。

| 元データ | 将来の新用の名前 | 方針 |
|---|---|---|
| `works` | `exr_works` | 既存 `works` を変更しない |
| `news` | `exr_news` | 既存 `news` を変更しない |
| `page` | `exr_page` | 既存固定ページと新用内容を分離する。公開 URL を成立させるアダプターは次段階 |
| `works_category` | `exr_works_category` | 名前・スラッグ・説明・親子関係を新用へ対応させる |
| `works_package` | `exr_works_package` | デザインテイストの新用分類 |
| `works_tag` | `exr_works_tag` | 新用タグ |
| 新用 CF7 | `wpcf7_contact_form` の新用レコード | CF7 の投稿タイプは維持し、専用識別で旧フォームから分離する |
| 新用メディア | `attachment` の追加候補 | 本番添付 ID・既存ファイルを上書きしない |
| `column`・`column_category` | なし | 本番の同じデータを共有するため、ローカルから輸送しない |

- 出典識別は `exterior-exone-renewal` と Local サイト ID を基準に安定させる。実行 ID はデータの同一性には用いない。
- 各対象に「出典サイト＋元の種別＋元 ID」の論理識別子を付ける。移行先の数値 ID は未割り当てのままにする。
- 同じタイトル、スラッグ、元の数値 ID、ファイル名だけでは、移行先の既存データと同一視しない。
- 将来の新用レコードには専用のデータ群識別、元論理識別、フォーム役割を保持する想定とする。予定のメタ名は `_exr_dataset`、`_exr_source_key`、`_exr_form_role`。対象環境で既存使用がないか確認するまで取り込み可能とは判定しない。
- フォーム役割は `personal`・`corporate`・`entry`。元の `_exterior_exone_contact_form` / `_exterior_exone_recruit_form` を根拠に照合し、タイトルだけの推定はしない。識別なし・重複は保留またはエラーとして報告する。
- `exr_` を使うことだけでは旧テーマへの非混入は保証されない。公開性、検索、REST、サイトマップ、キャッシュ、URL 振り分けの検証は後続のアダプターと本番複製で行う。

### 内容とメタの許可範囲

| 種別 | 取り出す内容 |
|---|---|
| 投稿・固定ページの共通項目 | 元 ID・元タイプ、タイトル、本文、抜粋、スラッグ、公開状態、作成・更新日時、親、並び順。投稿者のユーザーデータは入れず、移行先投稿者の割り当てが必要であることを記録する |
| 施工事例 | `_exterior_exone_works_image_main`・`_exterior_exone_works_image_exterior`・`_exterior_exone_works_image_perspective`・`_exterior_exone_works_image_plan`、`_exterior_exone_works_on_top`、旧所在地 `_exterior_exone_works_area`。旧ギャラリー `_exterior_exone_works_gallery` が現れた場合は順序付き参照として扱う |
| お知らせ | `_thumbnail_id` と共通項目。本文の HTML 等を実行しない |
| 固定ページ | `_wp_page_template`、存在する場合の `_thumbnail_id`、共通項目。`_wp_old_date` は履歴値として保存可能だが公開日や転送を自動変更する根拠にはしない |
| 分類 | 施工事例用 3 分類の元 ID・種別・名称・スラッグ・説明・親、および対象施工事例との関係 |
| 添付 | タイトル・説明・キャプション・MIME・元親情報、`_wp_attached_file`・`_wp_attachment_metadata`・存在する場合の `_wp_attachment_image_alt`。元親が除外対象なら参照先を移行しない |
| CF7 | 識別情報、`_form`・`_mail`・`_mail_2`・`_messages`・`_additional_settings`・`_locale`。メール設定は非公開ファイルだけに保存し、送信や評価はしない |

- `_edit_last`・`_edit_lock` は除外。CF7 の `_hash` は移行先での再生成対象として除外する。空でも全メタを一括持ち出ししない。
- 許可リストにないキーは、キー名と件数だけを未分類として報告し、値をログ・パッケージへ無条件に追加しない。使途が判明するまで「完全に移行できる」とは扱わない。
- CF7 追加設定や本文に外部 URL、実行コード、Webhook に関わる文字列があっても、準備ツールが実行・取得・送信することはない。内容確認が必要な設定として識別する。
- PHP シリアライズ値は実行せず、スカラー・配列だけをデータとして解釈する。オブジェクト・未知の型・壊れた長さは拒否する。本文の HTML、ブロック JSON、スクリプトも文字列のまま保持する。
- `column` の本文・メタ・分類・仮記事は収集しない。ユーザー・認証情報・グローバル設定・プラグイン設定・受信履歴・コメント・リビジョン・ゴミ箱・自動下書きも対象外。
- `publish`・`draft`・`pending`・`future` 等の対象投稿状態は記録して保持する。公開への昇格はしない。想定外の状態は件数付きで報告する。
- コメントは移行 0 件とし、新用項目の予定値は `comment_status=closed`、`ping_status=closed`、`comment_count=0` とする。元サイトの値やコメントテーブルを更新しない。

### 参照と URL の扱い

- 親ページ、添付、施工事例の画像枠と順序、アイキャッチ、分類、フォームを論理識別子へ対応させる。保存値の元 ID も出典として残すが、移行先 ID として用いない。
- 固定ページはスラッグだけでなく、親をたどったフルパスで識別する。`/contact/thanks/` と `/recruit/thanks/` は別のページとして扱う。
- 同時作業中のサンクスページは、実際の DB スナップショットに存在する場合に収集する。仕様書があるだけでページを生成せず、noindex 等のテーマ側要件はアダプター待ちとして記録する。
- 本文の画像 URL、srcset、添付 ID、ブロック内参照、CF7 ショートコード等について、検出できた参照と未解決参照を分ける。未対応の記法を「参照なし」として成功させない。
- コラムへのリンクは共有コンテンツへの外部依存として保持する。リンクがあるからローカルのコラム本文を収集しない。
- テーマに直接書かれている画像・固定文言・リンク・支店別宛先等は DB のエクスポートだけでは完結しない。該当ソースファイルの相対パス・ハッシュ・未収録の責務を依存一覧へ記載し、テーマ PHP を実行しない。
- 本段階は現時点の添付全件（確認値 38 件）を payload 対象にし、利用先を「新用内容から参照」「除外コラムだけから参照」「参照なし」「判定保留」に分類する。分類は参考情報であり、除外判定ではない。コラム本文は出力せず、添付との関係判定に必要な参照識別だけ扱う。
- 添付の元親が除外対象のコラム等なら、出典の親識別を記録したうえで、移行先の親は未設定（0）候補とする。本番の同じ数値 ID の投稿へ結びつけない。
- 添付や派生サイズの実パスが uploads の範囲内であることを確認し、範囲外・シンボリックリンク・欠損・不正パスは安全に拒否または保留する。外部画像はネットワークで取得しない。
- 同じ画像ハッシュがあることは重複候補の情報にとどめ、添付メタの異なる既存画像への自動統合を決めない。

## 5. オフライン模擬照合の仕様

### 入力

1. 完成済みの準備パッケージ。
2. 任意の対象棚卸しファイル。接続情報ではなく、取得済みのレコード・名前・URL・専用識別・ファイル情報と、どの項目が確認済みかを表すデータ。

対象ファイルを与えなくてもパッケージ自身の整合性は検査できる。ただし、対象環境と衝突しないという結論は出さない。

既存の `docs/production-url-inventory-20261015.json` を使う場合は、**固定ページ・コラムの ID と URL に限る部分的な棚卸し**として扱う。本番の全投稿タイプ名・ターム・フォーム・メディア・設定が空であるとは解釈しない。未知と空集合を別の状態で表す。

### 出す結果

下表は必要な区別と状態名の例。実装担当が採用する名前が異なっても、同じ区別が機械可読な結果と短い報告に現れればよい。

| 状態 | 意味 |
|---|---|
| `valid_package` | 準備パッケージ自身の検証に合格した |
| `would_add` | 完全性が明示された合成対象で、新しい論理項目として追加する想定 |
| `would_reuse` | 合成対象で、専用の出典識別が一致した新用項目を再利用する想定。タイトル一致では判定しない |
| `conflict` | 名前、専用識別、参照、階層、ファイル、形式等に解消が必要な衝突がある |
| `needs_review` | 未分類メタ、未対応参照、公開内容、旧 URL 互換等に人または次段階の確認が必要 |
| `unknown_target` | 対象棚卸しがない・部分的であり、本番衝突の有無を判定できない |

- 全体に `preparation_only` と「取り込み不可」を表示する。`ready_for_production`・`safe_to_import` といった本番適用可能な状態は出力しない。
- 保護対象の本番ページ・コラムに対する update / delete / replace は計画に含めない。既存と同じタイトル・URL・数値 ID があっても、新用データを同じ本番レコードへ寄せない。
- `/works/`・`/column/`・既存支店 URL 等は、既存 URL の削除や上書きで解決せず、「表示を切り替えるアダプターが必要」と報告する。
- 専用投稿タイプ・分類名の既存使用、同じ専用出典識別が複数項目に付いている状態、親子循環、参照先欠損、同一フルパスの重複、添付同名異内容、フォーム役割の重複を検出する。
- 再実行の模擬試験では、一度目の想定結果を**メモリ上の合成対象**へ反映し、二度目が重複追加にならないことを確認する。実 DB の冪等性が検証済みとは記載しない。
- 出力先だけに新規レポートを作成し、入力パッケージ・対象棚卸し・既存ファイルを変更しない。
