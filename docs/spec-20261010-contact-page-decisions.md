## 3. 既定（呼び出し側が決めた。変えたい場合はユーザーに確認）

### URL・テンプレート・遷移
- URL は `/contact/`（固定ページ `contact` = ID 78、タイトル「CONTACT」。2026-10-10 に WP-CLI で作成済み。テンプレートは `page-contact.php`）
- ヘッダー・ドロワー・フッターの「CONTACT / お問い合わせ」（`inc/menus.php` `exterior_exone_contact_item()`、いまは `#`）を `/contact/` にする。支店モードでは `exterior_exone_store_link()` で `?store=<slug>` が付く（既存の仕組み）
- `?store=<slug>` 付きで開いたとき: 「個人のお客様」とその支店を選択済みにし、「お問い合わせ方法」の 3 ボタンまで表示した状態で読み込む。ページ自体も支店モード（黒ヘッダー・支店フッター）になる（既存の仕組み）
- 支店の並び・名前・電話番号・受付時間・LINE の URL は `inc/store-data.php` の 6 拠点データから引く（二重管理しない）。東京オフィス（下書き）は出さない

### 画面の挙動（guide `853:568`〜`869:614` のとおり）
- 読み込み時は「個人のお客様 / 法人のお客様」の 2 択だけ（1 画面に収める）。ホバーとアクティブ（選択中）で色反転
- 個人 → 「お問い合わせ先店舗」6 支店のボタンが現れる。法人 → 法人用フォームが現れる
- 支店を選ぶ → 「お問い合わせ方法」（メールで相談する / LINEで相談する / 電話で相談する）が現れる。LINE はその支店の `line_url` を新しいタブで開く。電話はその支店の電話番号と受付時間を表示（SP は `tel:` で直接発信）。メールはその支店宛の個人用フォーム
- 選択を変えたとき: 下の段（方法・フォーム・電話）は選び直した内容に合わせて切り替える。入力途中の内容は消さない（同じフォーム要素を使い回す。支店の切り替えは隠しフィールドの値を変えるだけ）
- 出現はカンプに注釈が無いので、短いフェードイン（既存の `[data-reveal]` と同程度・0.3 秒前後）。アニメーションの速度は報告で確認

### Contact Form 7 の使い方
- フォームは 2 本: 「お問い合わせ（個人）」と「お問い合わせ（法人）」。**フォームの雛形（フォームタグ・メールの文面・送信先）はテーマのコード（`inc/contact-forms.php`）を正とし**、WP-CLI（`wp eval`）または管理画面から呼べる関数で CF7 に登録する。本番にも同じ手順で入れる。登録後は管理画面（お問い合わせ）で送信先・文面を変えられる
- 支店ごとの送信先: 個人フォームに支店の隠しフィールドを持たせ、CF7 の `wpcf7_before_send_mail` でその支店のアドレスに宛先を差し替える（アドレスはテーマのデータ。支給されるまで仮の `contact-<slug>@example.com`）。法人は本社の仮アドレス `info@example.com`
- 送信は CF7 の AJAX（ページ遷移なし）。完了メッセージ・エラーメッセージは CF7 の仕組みで同じページに出す。確認画面はテーマの JS（CF7 の送信前に入力値を一覧表示し、「送信する」で CF7 の送信を呼ぶ）
- CF7 の既定 CSS は読み込まない（`wpcf7_load_css` false）。見た目はテーマの CSS。CF7 が出す markup（`.wpcf7-form`、`.wpcf7-form-control`、`.wpcf7-not-valid-tip`、`.wpcf7-response-output`）に対してスタイルを当てる
- CF7 が作った既定の「Contact form 1」（ID 77）は 2026-10-10 に削除済み

### 対象外・保留
- 迷惑メール対策（reCAPTCHA 等）は今回は入れない。本番公開前に CF7 のインテグレーション（reCAPTCHA v3）でキーを設定する運用（公開前チェックリストに書く）
- 自動返信・必須項目・エラー表示・同意チェックは AskUserQuestion 2 回目で確認（§4 に追記）

## 6. ローカルのメール確認（2026-10-10 調査）

- Local の **Mailpit** がこのサイトで動いている。PHP の `sendmail_path` は Mailpit の sendmail（SMTP `127.0.0.1:10011`）。`wp_mail()` / CF7 の送信はすべてここに溜まり、実際には外へ出ない
- 受信箱の API: `http://127.0.0.1:10010/api/v1/messages`（一覧。`?limit=`）、`/api/v1/message/<ID>`（本文・宛先・From）。画面は Local アプリの「Mailpit」タブ（同じポート）。S3 の検証は **この API で宛先（To）・件名・本文・自動返信の有無を確認する**（ログではなく実物）。テスト前に `DELETE /api/v1/messages` で空にしてよい

## 追記（2026-10-14）郵便番号 → 住所の自動入力

- ユーザー指示「郵便番号を入力したら自動で住所も入力」。個人・法人の両フォームで、`your-zip` に 7 桁入ったら zipcloud API（https://zipcloud.ibsnet.co.jp/、無料・登録不要・CORS 可）に問い合わせ、都道府県+市区町村+町域を `your-address` に入れる（`js/contact-zip.js`）。番地以降は手入力
- 利用者が自分で書いた住所は上書きしない（空か前回の自動入力のままのときだけ）。全角・ハイフンは数字だけに直して問い合わせ、欄を離れたときに欄の値も数字だけにする。見つからない・通信失敗は何もしない
- 採用の応募フォーム（`/recruit/entry/`）にも郵便番号欄があるが、今回は対象外（指示が CONTACT のみ）
