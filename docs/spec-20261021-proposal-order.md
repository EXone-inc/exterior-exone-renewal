# 提案事例の表示順変更

作成日: 2026-10-21。ユーザー依頼: 管理画面の提案事例一覧でドラッグして順番を変更・保存し、公開一覧と詳細ページ内の事例一覧へ同じ順番を反映する。

## 対象と維持条件

- 本番共存モードでは既存 `exone-proposals` の「すべて」一覧に操作を追加する。対象は所有確認済み `exr_works` / `exr_stored` の公開・下書き事例。ゴミ箱は対象外。
- 通常ローカルでは新テーマの `works` に同じ保存・表示方式を適用する。標準投稿一覧のページ送り・検索を壊さないため、提案事例メニュー配下の専用「表示順」画面を許容する。
- 本番旧 `works`、旧テーマ、ニュース、コラム、分類、フォーム、画像、PHP 設定は変更しない。本番現在の 14 件のタイトル・本文・画像・公開日時・URL・公開状態・取り込み識別は維持する。
- TOP の提案事例は従来の公開日順と最大件数を維持する。依頼範囲は `/works/` と詳細ページ内の一覧のみ。
- 初期表示・ファイル配置で DB を書き換えない。バックアップ・自動移行・テーマ切替を追加しない。

## 操作

1. 全件一覧の各行にドラッグ用ハンドルを表示する。マウスのほか上下移動ボタンでも操作できる。
2. 移動中は画面上だけ並び替える。「表示順を保存」を押すまで公開側を変更しない。
3. 未保存・保存中・保存済み・競合/失敗を日本語で示す。保存中の二重送信を防ぐ。未保存のまま離れる場合は変更が失われることを案内する。
4. 公開のみ・下書きのみ・ゴミ箱などの部分一覧では並べ替えを許可せず、全件一覧への導線を出す。部分 ID リストで全体順位を上書きしない。
5. 行内に既存のゴミ箱フォームがあるため、表全体を別の form で包まない。保存用フォーム/通信を独立させる。

## 保存形式と表示順

保存先は対象投稿の標準 `menu_order` のみ。専用の順序メタやサイト共通 options を増やさない。保存時の先頭から `-N, -(N-1), …, -1` を設定する。

共通の取得順を `menu_order ASC, post_date DESC, ID DESC` とする。

- 初期値が全件 0 の既存サイトでは従来の日付順を維持する。同日同時刻の同順位は ID 降順で確定する。
- 保存後に新規追加した事例は初期値 0 のため、保存済み事例の後ろに並ぶ。次回の全件保存で好きな位置へ動かせる。
- 下書きも全体順位を持つが公開側へは出さない。公開にすると、その保存位置へ表示される。
- ゴミ箱は順位保存の対象外とし、移動前の順位を保持する。復元時は保持順位と日付/ID の補助順で入る。次回保存で全体順位を再採番できる。
- 既存の公開条件、日付条件、テイスト絞り込み、支店クエリ引き継ぎは変更しない。絞り込み後も元の全体順を保つ。

## 保存の検証・競合対策

- 管理者権限 `manage_options`、POST、操作専用 nonce、サイトの有効モードを検証する。共存時の旧 `works` ID を拒否する。
- ID 配列は正の整数、重複なし、件数上限付きで厳密に検証する。最新の対象全件 ID 集合と完全一致しない要求を拒否する。
- 表示時の対象集合・状態・順位について改ざんできない版情報を付ける。古いタブ、同時並べ替え、追加、ゴミ箱移動、復元で対象状態が変わった場合は上書きせず再読込を案内する。
- 共存モードは既存 `exterior_exone_proposal_valid()` と所有識別・一意キー検証を使う。同時保存は既存事例/分類操作と同じ advisory lock と InnoDB transaction を使い、ロック下で最新状態を再検証する。
- 通常ローカルも対象の投稿型・許可状態を確認し、トランザクション内で順序の全件更新を一体化する。個別投稿内容を書き戻さない。
- SQL の WHERE には ID・投稿型・必要な保存状態を付け、変更列を `menu_order` に限定する。公開日時・更新日時を変更する `wp_update_post()` の一括呼び出しは使わない。
- 一件でも不整合/エラーならコミット前に全変更を取り消す。確定結果が不明なエラーでは自動再送せず再読込を案内する。確定後は対象 post/query cache を無効化する。

## 変更経路

- `inc/works-page-data.php`: 通常 archive のメインクエリと `exterior_exone_works_page_cards()` の取得を同じ共通順序へ。
- `inc/coexistence.php`: priority 90 の `exterior_exone_coexistence_main_query()` が日付順を再設定するため、`works-list` に限定して共通順序へ。ニュース・検索などに広げない。
- `inc/coexistence-proposal-admin.php` と対応 CSS/JS: 全件一覧で順序操作、保存入口、バージョン情報。ローカル用共通処理は小さな独立ファイルへ分離可能。
- `inc/top-data.php`: 既存 `orderby=date` を保持。共通 `exterior_exone_content_posts()` 全体を無条件に並べ替えない。
- 本番 PHP 7.4 に対応する。配布は当日の本番ソースと比較して必要な新テーマファイルだけを更新し、以前の Figma 反映などを古いローカルファイルで巻き戻さない。

## 受け入れ検証

- 未保存のドラッグで DB/公開順不変。保存後、再読込した管理画面・公開一覧・代表詳細の一覧で同じ公開 ID 順。
- 通常ローカルと共存モードの両経路を確認。初期全 0、明示順保存、新規 0 追加、下書き、ゴミ箱/復元、同日時の補助順を確認。
- ID 欠落・重複・旧 ID/別型混入・不正 nonce・権限不足・古い版・途中失敗で部分更新が発生しない。
- 保存前後で対象投稿の `menu_order` 以外、旧投稿・メタ・分類・共有設定が不変。TOP の取得順も不変。
- 管理画面デスクトップで実際にドラッグ→保存を検証し、狭い画面/キーボードで上下移動操作を確認する。PHP 7.4 構文チェックと対象回帰を行う。

追加のユーザー回答を必要とする未確定事項はない。現在の公開順そのものをこちらの判断で変更せず、機能配置時点では現行順を維持する。
