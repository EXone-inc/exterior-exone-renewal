## 1. 背景・目的

テーマを変えるだけでは、WordPress の投稿・固定ページ・フォーム等のデータは別の内容に切り替わらない。今回の目的は、現行サイトのデザインと内容を保存しながら、新テーマを選んだときだけローカル由来の内容を表示し、コラムだけは両テーマで同じ本番記事を利用できる状態を作ることである。

新テーマから旧テーマへ戻す操作は、データを復元・再インポートする作業を必要としないことを到達条件とする。共通のコラムを後日更新した場合、その更新は両テーマに表示される。旧テーマへ戻してもコラムだけ過去の内容に巻き戻すことはしない。

本番へのファイル追加や新規データ追加も本番変更である。「テーマを有効化しないから影響がない」とは扱わない。本番の表示、データ、設定、処理負荷、メール・Webhook、キャッシュ等への影響があり得る段階では、復元可能なバックアップと具体的な手順を用意し、実施前にユーザーの確認を得る。

## 2. スコープ

### やること

- 現行本番の基準記録、復元可能なバックアップの要件整理、復元先の隔離。
- 新テーマを独立したテーマとして扱い、旧テーマ・親テーマを保持する。
- 旧テーマ用データ、新テーマ用データ、共通コラムの区分を明確にする。
- 新テーマ用の施工事例・お知らせ・固定ページ・フォーム・メディアの追加対象と参照対応表を用意する。
- 本番コラムの本文・URL・メディア・分類・SEO 情報を保持して新デザインで表示する。
- PHP を含む実行環境の互換性、プラグイン、URL、キャッシュ、新旧切り替えを隔離環境で検証する。
- 検証結果、残る不適合、バックアップ、適用範囲、戻し方をまとめ、本番への変更前にユーザーへ提示する。

### やらないこと

- 本仕様書の作成を根拠にした本番への変更・バックアップジョブの実行・テーマ有効化。
- ローカルの DB 全体やサイトバックアップを本番に復元すること。
- 既存投稿・固定ページ・コラム・フォーム・添付ファイル・ターム・SEO メタの上書きや削除。
- `home`、`siteurl`、公開設定、フロントページ設定、パーマリンク、CPT UI、プラグイン一覧等のローカル値による上書き。
- 旧親テーマ、旧子テーマ、WordPress 本体、プラグイン本体の改変。
- 併存のためのプラグイン無効化・更新、PHP 更新を無確認で行うこと。
- この作業に伴う新しいデザインの制作、仮原稿の本番原稿化、SEO 順位の成果保証。

### 共通のデータ境界

| データ | 旧テーマ選択時 | 新テーマ選択時 | 保存方針 |
|---|---|---|---|
| 施工事例・お知らせ | 現行本番 | ローカル由来の新テーマ用内容 | 同名の既存投稿へ上書きしない。旧テーマの一覧や検索に追加分を混ぜない |
| 固定ページ・TOP・メニュー | 現行本番 | ローカル由来の内容・構成 | 本番ページの本文・スラッグ・親子関係・テンプレート・メニュー設定を維持する |
| 問い合わせ・採用応募 | 現行本番フォーム | 新テーマ用フォーム | 旧フォームと送信設定を保持し、新用フォームを別に識別する |
| コラム | 本番の同じ記事 | 本番の同じ記事を新デザインで表示 | 記事本文・ID・URL・日付・分類・SEO メタ・添付参照を共有する |
| メディア | 既存画像の参照が維持される | 既存コラム画像とローカル追加画像 | 既存ファイルを残し、追加ファイルは名前・参照を衝突させない |
| 全体設定・プラグイン設定 | 本番の値 | 本番の値を前提とする | デザインごとの違いで共有設定を書き換えない |

- ユーザーストーリー: サイト管理者として、検証中に本番の表示や問い合わせを変えず、何を戻せるか確認したい。

  - [ ] AC-01-3: §7 の全バックアップ範囲について、取得物、保存場所、日時、サイズ、検証結果、対象外が分かる一覧がある。BackWPup の成功表示だけを完全性確認の代わりにしない。

  - [ ] AC-03-2: 旧テーマの投稿・固定ページ・フォームと、新テーマ用の同名内容が別の識別情報で区別される。既存 ID・スラッグへの上書き、タイトルだけでの同一視を行わない。
  - [ ] AC-03-3: 旧テーマ表示中の一覧・サイト内検索・関連投稿・記事/検索/コメントの各 RSS・サイトマップ・公開 REST 応答から、追加された新用記事や固定ページへ意図しない導線が出ない。管理画面では新用データを区別できる。新用コメントは移行せず、コメント・ping を閉じる。

## 6. オープン論点・公開前の保留事項

### 確定済みのため聞き直さないこと

- 旧テーマでは現在の本番の内容、新テーマではローカルの内容を使う。
- 既存本番メディアを残し、ローカルメディアを追加する。
- 本番コラムは本文・URL を共有し、新テーマでは新デザインにする。
- ローカルの仮データを含む現状で検証してよい。一般公開前に内容確認を行う。
- `/retest/` は本番設置位置であり、検証用とは扱わない。

### 調査・検証で解決する事項

- Q1: Xserver のサーバーパネルで DB・ファイル保存先・取得できる世代まで読み取り確認済み（§10）。2026-10-15 世代のバックアップ取得と PC 保存はユーザー承認済み。取得対象の完全性と隔離先への復元可否を引き続き確認する。
- Q2: 本番の各 CPT・タクソノミー、パーマリンク、SEO 出力の登録元・優先順位は何か。CPT UI、Custom Post Type Permalinks、AFFINGER、XML Sitemap の具体的設定を確認する。
