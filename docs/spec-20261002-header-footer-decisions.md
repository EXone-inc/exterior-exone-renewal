# ヘッダー・フッターの出し分け（コーポレート / 支店）— 決定事項

- 作成: 2026-10-02

- 本ファイルは、ユーザーの指示・回答と、それを受けて呼び出し側が決めた既定をまとめたもの。仕様書（`docs/spec-20261002-header-footer.md`）と食い違う場合は**本ファイルが正**

## 1. ユーザーの指示（原文の要旨）

- コーポレートサイトと支店ページとで、ヘッダーとフッターを出し分ける。それぞれのカンプは `670:357` の中にある
- 切り替えのタイミング
  - コーポレートからヘッダーの支店ページのメニューを選んで遷移したとき → 支店用のヘッダー・フッターになる
  - 支店側で「コーポレート」のメニューを選んで遷移したとき → コーポレート用に戻る
- URL の例（本番）。ローカルではローカルの URL で同じ形にする
  - コーポレート: `https://exterior-exone.com/dx/`、`https://exterior-exone.com/works/`
  - 支店（青森支店の場合）: `https://exterior-exone.com/dx/?store=aomori`、`https://exterior-exone.com/works/?store=aomori`

## 3. 支店モードの判定

- 支店モード = 次のどちらか
  1. 支店ページ `/store/<slug>/` を表示している（既存の `exterior_exone_current_store()`）
  2. URL に `?store=<slug>` が付いていて、`<slug>` が `exterior_exone_stores()` のキー（sendai / totsuka / morioka / aomori / hachinohe / hirosaki）のどれか
- それ以外はコーポレート。`?store=` の値が不正（存在しない slug）のときもコーポレート
- 支店一覧 `/store/` は、`?store=` が無ければコーポレート
- `store` を WordPress の公開クエリ変数として**登録しない**（登録すると静的フロントページ `/?store=aomori` が投稿一覧扱いになる）。`$_GET['store']` を `sanitize_key()` して支店のキーと照合する
- 1 と 2 が両方あって食い違う場合（`/store/sendai/?store=aomori`）はページ（1）を優先

## 4. 支店モードでのリンク

- **支店モードの間は、サイト内のリンクすべてに `?store=<slug>` を引き継ぐ**（ヘッダー・フッター・SP メニュー・ロゴ・本文中のボタンやカードのリンク・投稿タイプのアーカイブや個別記事へのリンク）。コーポレートへ戻るのは「コーポレートサイト」を押したときだけ、というユーザー指示のため
- 例外（`?store=` を付けない）
  - 「コーポレートサイト」→ `/`（同じタブ）
  - 支店ページそのもの `/store/<slug>/`（ページ自体で支店が決まるので不要）。STORES のドロップダウン・フッターの STORE 列・SP メニューの STORE から別の支店を選ぶと、その支店に切り替わる
  - 外部リンク（LINE・電話・exone-package.com・SNS）、`#` のままの未設定リンク、ページ内リンク（`#...`）
- 実装方針: `home_url()` の直書きを共通ヘルパーに置き換える。**`home_url` フィルタは使わない**（canonical・REST・フィードなどにまで付くため）。`<link rel="canonical">` は `?store=` なしのまま（コーポレートの URL を正とする）
- 支店モードでの行き先
  | 項目 | 行き先 |
  |---|---|
  | ロゴ（ヘッダー・SP メニュー上部・フッター） | 支店の TOP `/store/<slug>/` |
  | 「○○支店」 | 支店の TOP `/store/<slug>/` |
  | TOP | 支店の TOP `/store/<slug>/` |
  | DX EXPERIENCE / 新しい外構体験 | `/dx/?store=<slug>` |
  | PLANS / プラン一覧 | `/plans/?store=<slug>` |
  | WORKS / 事例一覧 | `/works/?store=<slug>` |
  | STORES | 遷移せずドロップダウン（6 支店 → `/store/<slug>/`） |
  | コーポレートサイト | `/` |
  | CONTACT / お問い合わせ・お知らせ・コラム | コーポレートと同じ（現在は未設定の `#`） |
- **WORKS / 事例一覧のリンク先を `#` から `/works/`（施工事例のアーカイブ）に変える**（コーポレートも）。ユーザーの URL 例に `/works/` があるため。ページの中身は未実装（`index.php` の素の一覧）のままで、今回の範囲外

## 12. 実装メモ（2026-10-02）

- S1 は generator が途中で停止したため、作業ツリーを引き継いで呼び出し側が仕上げた。S2 は呼び出し側が直接実装
- 追加した関数（`inc/store-mode.php`）: `exterior_exone_store_mode()`（支店データ or null）/ `exterior_exone_is_store_mode()` / `exterior_exone_store_link( $url )`（支店モードなら `?store=` を付ける）/ `exterior_exone_brand_url()`（ロゴ・TOP の行き先）/ `exterior_exone_store_mode_html_attribute()`（`<html data-store-mode>`）。`inc/menus.php`: `exterior_exone_store_global_menu_items()` / `exterior_exone_store_drawer_menu_items()` / `exterior_exone_store_footer_menu_items()` / `exterior_exone_nav_menu()`（支店モードでは割り当てメニューを使わず fallback を出す）。項目の `modifier` キーで `<li>` に修飾クラス（CONTACT ボタン = `p-gnav__list__item--button`）
- 支店モードの印は 2 つ: `<body class="is-store-mode">`（見た目の切り替え）と `<html data-store-mode>`（`--header-height` を 113 にする。`:root` で導出しているトークン = PLANS のタブ位置などもこの値で動かすため、body ではなく html 側に付けた）
- PC の「○○支店」とメニュー文字の高さは、既存のコーポレートのヘッダーと同じく「ロゴの上下中央に揃える」作法（文字の上端 y41.5。カンプは y45）。CONTACT ボタンの上下中央も同じ線に揃えた
- **Q2（VR）は回答が無かったため推奨の (a) で実装**: 支店モードの PC だけ、VR を黒帯の下から始め、ヘッダーと合わせて 1 画面に収める（`css/dx-vr.css` 末尾）。メニューを左へ寄せる既存の上書きは支店モードでは解除
- 新しい内部リンクを書くときは `exterior_exone_store_link( home_url( '/…/' ) )` を通すこと（通さないと、支店モードでそのリンクを押したときコーポレートに戻ってしまう）

## 14. 支店用ヘッダーの置き方を変更（2026-10-06、ユーザー決定）

- §2 の「いまと同じく重ねる」を**取り消し**。黒ベタ（不透明）のヘッダーを重ねると、画面に固定される演出（DX のステップ・Explorer・PLANS の選択画面・FV）の上部が隠れることが分かった（ユーザーのスクリーンショット: DX ステップの「01」が欠ける、PLANS の FV の上が隠れる）
- 新しい決定: **支店モードの PC では、内容をヘッダーの下から始める**（SP と同じ考え方）。ヘッダーは流れの中の追従ヘッダー（sticky、top 0）にし、FV から始まるページでも写真に重ねない。固定される演出はヘッダーの下に固定し、高さは `100vh − ヘッダー` にする
- 実装: `style.css` の `:root[data-store-mode]`（PC）で `--fv-pin-top / --fv-pin-height / --dx-pin-top / --dx-pin-height` をヘッダー基準に（TOP・企業情報・ハイエンドの FV ピン、TOP / 支店の DX セクション）。`css/dx.css`: ステップの舞台の縮尺とExplorer の舞台の top / 高さ。`css/plans.css`: `--plp-scroll-offset`・`--plp-select-h`・選択画面の縮尺。`css/dx-vr.css`: padding で下げる手当ては不要になったので削除（フレームの高さだけ残す）。`js/dx-explorer.js`: 固定の始まりを sticky の top から読む（コーポレート・SP は従来どおりの値になる）
- 高さ 113（1920 基準）はカンプどおりで変えていない（1413px 幅では約 83px）
- 2026-10-06: PC の「○○支店」はロゴの上下中央ではなく、カンプどおり文字枠 y45（ベースラインがロゴの下端 66 に揃う）に下げた（`--store-name-shift` PC = 3.5）。ユーザー指示「ロゴの下部に合わせる」。SP は変更なし

- **SNS リンクの実値（2026-10-10 ユーザー支給）**: フッターと SP ドロワーの NOTE `https://note.com/exterior_exone` / Instagram `https://www.instagram.com/exone_recruit/` / Facebook `https://www.facebook.com/EXone.inc/` / 公式 LINE `https://lin.ee/yhxQKWD`（`inc/menus.php` `exterior_exone_sns_items()`・定数 `EXTERIOR_EXONE_LINE_URL`）。LINE は支店モード（支店ページ・`?store=`）ではその支店の `line_url` に出し分け（ユーザー指示）。4 つとも外部サイトなので `target="_blank" rel="noopener"`
- **残っている `#` リンク（2026-10-10 ユーザー回答）**: RECRUIT / 採用情報（ヘッダー・ドロワー・フッター・TOP の RECRUIT セクションの VIEW MORE）と、お知らせ・コラム（ドロワー・フッター）は**ページができるまで `#` のまま**。TOP の PLANS セクションのパッケージプランの VIEW MORE は `/plans/#package`（支店モードは `?store=` 付き）に接続済み
- **中身が画面より短いページでフッターの下に黒い帯（2026-10-10、iPad Pro 13 縦 1032×1376 の `/store/`・`/contact/`）**: `body { display:flex; flex-direction:column; min-height:100vh }` + `.l-main { flex:1 0 auto }` でフッターを画面の下端まで下ろした（`style.css`）。追従ヘッダー・横スクロール・長いページの高さに影響なし

## 2026-10-22 更新: コーポレートの公式LINEアイコン

ユーザー指定により、コーポレートのヘッダーが表示される場合はフッター・SPハンバーガーメニューのLINEアイコンを非表示にする。ヘッダーと同じ `exterior_exone_store_mode()` 判定でSNS配列を出し分ける。支店ページおよび `?store=<slug>` の支店表示は従来どおり各支店のLINEリンクを表示。他のSNSとお問い合わせページ内のLINE導線は変更しない。

同日追記: LINE非表示時の左右バランスを保つため、フッター・SPメニューのSNSは固定4列から表示件数に応じた均等列へ変更。コーポレート3件・支店4件とも全体を中央に配置する。
