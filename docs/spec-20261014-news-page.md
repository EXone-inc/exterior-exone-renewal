## 1. 背景・目的

TOP の NEWS セクションの「VIEW MORE」とメニューの「お知らせ」の行き先になるページが未実装（現在 `/news/` は `index.php` の仮表示、メニューの「お知らせ」は `#`）。お知らせは短い告知が中心なので、詳細ページは作らず、一覧だけで全文を読めるようにする。見た目はコラム一覧に揃え、コラムのカテゴリータブの位置を「年月」の絞り込みにして、過去のお知らせを月単位で探せるようにする。

## 2. スコープ

### やること
- 一覧 `/news/`（見出し → 年月で絞り込み → お知らせ 10 件（全文・押せないカード）→ ページ送り）。テンプレート階層上は `archive-news`
- 年月の絞り込み `?ym=YYYY-MM` とページ送り `/news/page/<N>/`
- 個別 URL `/news/<slug>/` の一覧への 301 転送（個別のテンプレート `single-news` は作らない）
- TOP の NEWS カードのリンク先を `/news/` に変更（`exterior_exone_news_cards()` の URL だけ。`exterior_exone_store_link()` 経由）
- コーポレートでは半透明グラデのオーバーレイヘッダー（コラムと同じ扱い）、支店モード（`?store=`）の引き継ぎ
- ハンバーガーメニュー・フッターの「お知らせ」（コーポレート・支店とも、現在 `#`）を `/news/` に接続
- 検証用の【仮】お知らせの追加（WP-CLI のみ。§4「仮データ」）
- `CLAUDE.md` のフレーム対応表に NEWS の行を追記

### やらないこと（範囲外）
- お知らせの詳細ページ（`single-news.php`）。前後ナビ・一覧へ戻るリンク・詳細末尾の COLUMN セクション
- お知らせの投稿画面（`inc/meta-boxes.php` のフォーム）・CPT 登録（`inc/post-types.php`）の変更。タクソノミーの追加
- TOP の NEWS セクションの見た目・テンプレート（`template-parts/top/section-news.php`）の変更。変えるのはカードのリンク先だけ
- コラムページの見た目・挙動の変更（**1px も変えない**。共有のための構造的な変更はしてよいが、表示結果が同一であること）
- 説明文のリッチテキスト化・URL の自動リンク化
- WordPress 標準の日付アーカイブ（`/news/2026/05/` 形式）への対応
- 一覧からの個別お知らせへのアンカー（転送先で該当のお知らせまでスクロールする等）
- 本番用のお知らせ内容の作成、画像の最終調達（画像は既存メディアの使い回し = 差し替え前提の仮画像）
- パンくず・SNS シェア・検索

## 3. 機能一覧

> 共通の前提（全機能）
> - デザインの正はコラム一覧。**同じ幅（375 / 1920）の `/column/` のスクリーンショットと見比べて**、構成・配置・配色・タイポグラフィ・余白感が一致すること（px 完全一致は求めない。`CLAUDE.md`「忠実再現」）
> - 一致しない点として許されるのは、①カテゴリーのチップが無いこと、②見出し・絞り込み見出し・文言の差、③抜粋ではなく説明文の全文を出すこと（カードの高さが内容で変わる）、④カードが押せないこと（ホバーの変化が無い）だけ
> - 値はトークン経由。ブレイクポイントは 1024 / 1025 のみ。出力はすべてエスケープ。内部リンクは `exterior_exone_store_link()` を通す。DB 操作は WP-CLI のみ

### F-02: 一覧ページ `/news/`（見出し・全文の押せないカード・0 件表示・ヘッダー）

- 概要: コラム一覧と同じ組みで、見出し → 「年月で絞り込む」+ タブ列（このスプリントではタブが表示されるだけでよい。押したときの絞り込みは F-03）→ お知らせ（公開日の新しい順に 10 件）→ ページ送りの順に並べる。各お知らせは「サムネイル（あれば）・日付・タイトル・説明文の全文」を出す押せないカード。コラムのカテゴリーチップの位置には何も出さない。コーポレートではヘッダーをコラムと同じ半透明グラデのオーバーレイにし、その分の上余白もコラムと同じにする
- Figma ノード: カンプ無し（正はコラム一覧。元ボード `875:50` / 参考画像 `875:30`）。見出し「NEWS」は TOP の NEWS PC `917:93` / SP `917:877`
- ユーザーストーリー: 来訪者として、TOP の「VIEW MORE」やカードから一覧に来て、お知らせの全文をその場で新しい順に読みたい。なぜなら、短い告知のために別のページを開き直したくないから。
- 表示仕様:
  - 見出し（`h1` 1 個）: 英字「NEWS」（コラムの「COLUMN」と同じ書体・色・大きさ）+ 和文「お知らせ」（コラムの和文リードと同じ書体・大きさ。PC・SP とも 1 行）
  - 絞り込み見出し「年月で絞り込む」（コラムの「カテゴリーで絞り込む」と同じ見た目）、タブ列の `aria-label`「お知らせの年月」
  - タブ: 先頭「すべて」、続いて公開済みのお知らせがある年月を新しい順（ラベル「2026年8月」形式）。見た目・選択中の表示はコラムのタブと同じ。年月が多くても省略せず折り返して並べる
  - カード（1 ページ 10 件・公開日の新しい順）:
    - 配置はコラムのカードと同じ（PC: サムネが左・文字が右 / SP: サムネが上・文字が下）。サムネは「画像」（アイキャッチ）。**画像が無いときはコラムと同じ gray2 の面**をサムネ位置に出す
    - 文字側: 日付 `YYYY.MM.DD`（`time` 要素、`datetime="YYYY-MM-DD"`）→ タイトル（`h2`）→ 説明文の全文
    - 説明文: コラムのカードの抜粋と同じ書体・大きさ・色・行間で、**行数で切らない（省略記号「…」も付けない）**。1 行以上の空行で段落を分け、段落内の 1 行改行は改行として表示する。前後の空白・空行は詰める。HTML・ショートコードとして解釈せず、文字のまま表示する（`<b>` などは文字として見える）。段落間はひと目で段落の切れ目が分かる程度の間隔。改行の無い長い文字列（URL など）も枠からはみ出さず折り返す。説明文が空なら説明文の要素を出さない
    - **押せない**: カード全体・サムネ・タイトルのどこにもリンクを置かない（コラムの全体リンク `<a>` に当たる要素は `<article>` / `<div>`）。ホバーしてもサムネの拡大・タイトルの下線・カーソルの変化など、見た目の変化が一切無い
  - 0 件時: タブ列の下に「該当するお知らせはありません」（コラムの 0 件表示と同じ見た目）。タブ列は出す
  - スクロールで出現する演出はコラムと同じ（JS 無効時は最初から表示）
  - ページ地はコラムと同じ white4
  - ヘッダー: コーポレートでは `body.has-fv-header`（オーバーレイヘッダー）。見出しの位置（ヘッダー下端からの距離）はコラム一覧と同じ。支店モードはコラムと同じく黒帯（sticky）のまま、上余白も支店モードのコラムと同じ
- CSS の持ち方（推奨。Generator は採った方式と理由を報告する）:
  - **推奨 A**: コラム一覧の CSS（`css/column-page.css`）とクラス名をお知らせでもそのまま共有し、お知らせで読み込む。お知らせ固有の差分（全文表示・押せないカードでホバーの変化を出さない等）だけを小さな別ファイルに持つ。ページ地・JS 無効時の表示などページ単位の指定はお知らせのページにも効くようにする
  - 代替 B: 一覧の共通部分を新ファイル（例 `css/post-list.css`）に切り出して両ページで読み、コラム固有（詳細・本文内の部品など）は `column-page.css` に残す
  - **複製はしない**（見た目のずれが将来発生するため）
  - どちらの方式でも、①コラムの表示結果は変えない（F-05 の AC で比較）、②「コラムのページかどうか」の判定（`exterior_exone_is_column_page()`）の意味は変えない（コラムの一覧・詳細だけが該当。お知らせは別の判定を設ける）、③お知らせの CSS は `/news/` 系以外のページでは読み込まない
- データ関数の置き場: `inc/news-page-data.php`（コラムの `inc/column-page-data.php` に倣う。一覧の文言・年月タブ・`ym` の解釈・一覧の URL・カード・ページ送り・説明文の表示用整形・個別 URL の転送をここに持つ）

### F-03: 年月の絞り込み（`?ym=`）とページ送り

- 概要: タブを押すとサーバー側でその年月に公開されたお知らせだけを表示する（`/news/?ym=YYYY-MM`）。10 件を超えるとページ送り（前へ・番号・次へ。見た目・番号の省略規則はコラムと同じ）を出し、2 ページ目以降は `/news/page/<N>/`（絞り込み中は `?ym=` を引き継ぐ）
- Figma ノード: カンプ無し（正はコラムのタブ・ページ送り。元 参考画像 `875:43`）
- ユーザーストーリー: 来訪者として、「2026年5月」のように月を選んでその月のお知らせだけを見たい。なぜなら、時期を覚えているお知らせを素早く探したいから。
- 仕様:
  - 年月の判定は投稿日（サイトのタイムゾーンの公開日時。カードに表示している日付と同じ基準）
  - 年月一覧は公開済み（`publish`）のお知らせだけから作る。下書き・予約投稿・非公開・ゴミ箱の月は出さない。リクエスト内で 1 回だけ集計して使い回す。永続キャッシュは件数の規模から不要（採る場合は、お知らせの公開・更新・削除・ステータス変更・日付変更で必ず破棄され、古いタブが残らないこと）

## 6. オープン論点（Generator は括弧内の既定で進め、変えた点・気づいた点を報告する）

ユーザーへの要確認は**無し**（2026-10-14 の 2 回の回答で解消）。以下は Generator 判断の既定。

- Q1: サイトマップからお知らせの個別 URL を外す … 既定: 外す（転送される URL を載せないため。F-04）。一覧 `/news/` はアーカイブとして従来どおり扱う
- Q2: CSS の共有方式 … 既定は F-02 の推奨 A（コラムの CSS とクラス名を共有）。B（共通ファイルへの切り出し）を選ぶ場合は理由を報告する。どちらでもコラムの表示結果は不変（AC-05-7）
- Q3: 和文の見出し … 既定「お知らせ」1 行（カンプ・TOP に和文が無いので最小にした）
- Q4: 1 ページの件数 … 既定 10 件（コラムと同じ）。全文表示でページが長くなりすぎると感じたら、変えずに報告する
