# Spec: 新テーマのお知らせ管理

- 作成日: 2026-10-20
- 起案: 本番の新テーマ用「お知らせ」を管理画面から登録・変更・削除できるように実装・反映する。今回はバックアップ不要。テーマ切替と本番公開画面の確認はユーザーが行う。
- 前提: PHP 7.4.33 を維持し、旧テーマ・旧データ・既存設定を保持する。
- デザイン元: Figma `msbO5SCyCUBUXQwXLUug4m`。既存 TOP お知らせ PC `917:93` / SP `917:877`、一覧の参考コラム `875:50`。今回の管理画面に専用カンプはなく、WordPress 管理画面の表示を用いる。公開側のデザイン変更はない。

## 1. 背景・目的

共存用のお知らせは通常の投稿一覧から非表示の保存領域にあり、現在は取り込み内容を確認する画面だけがある。管理者が新テーマ用のお知らせを運用できる専用画面を追加する。旧テーマで表示される記事や旧管理画面には変更を加えない。

## 2. スコープ

対象は新テーマが有効で共存機能が明示的に有効な場合の、お知らせの一覧・新規登録・編集・公開／下書き・ゴミ箱移動／復元。管理者権限を持つ利用者だけが操作する。共存機能を使わない通常のローカルサイトでは既存のお知らせ管理を維持する。

恒久削除、一括処理、予約公開、支店別分類、本文の HTML 編集、他のコンテンツ編集、既存画像の削除、テーマ自動切替は対象外。現状のお知らせに支店情報はなく、全店共通で表示され、閲覧時の `?store` だけがリンクへ引き継がれる。この動作を維持する。

## 3. F-01: 新テーマのお知らせを管理する

### 操作と入力

- 管理画面のトップレベルに「お知らせ（新テーマ）」を設ける。既存の「新テーマ用コンテンツ」からも専用編集画面へ案内する。
- 一覧でタイトル、表示日、現在の状態、画像の有無を確認し、新規登録・編集・ゴミ箱移動・復元を行う。ゴミ箱は通常一覧と区別する。
- 入力はタイトル（必須）、本文（任意・改行を保持するプレーンテキスト）、画像（任意）、表示日、公開／下書き。新規は下書きが初期値。
- 表示日はサイトのタイムゾーンで扱い、未来日は保存しない。新規の日付は当日が初期値で時刻は 00:00:00。既存記事は同じ日付なら既存時刻を保持する。日時指定や予約機構は追加しない。
- 画像は権限のある既存の画像メディアを選択・解除できる。標準メディアライブラリを使用し、画像の実体・親・タイトル・代替テキストをこの画面の保存で変更しない。画像を外してもメディアは残る。
- 本文は現在の公開表示と同じく HTML やショートコードとして解釈しない旨を示す。
- 削除操作はゴミ箱移動とし、元の公開／下書き状態へ復元できる。公開だった記事を復元すると新テーマ側の掲載対象へ戻ることを示す。
- 内部の取り込み識別子・ハッシュは利用者へ表示しない。既存確認画面の「元の公開状態」は、編集後のお知らせについて現在の状態であると誤解なく分かる表示にする。

### 受け入れ基準

- [x] AC-01: 新テーマの管理者にだけ専用メニューが表示され、一覧・新規・編集・ゴミ箱の各画面を利用できる。旧テーマ、共存無効のローカル、権限のない利用者では専用の保存入口も利用できない。
- [x] AC-02: タイトル・本文・画像・表示日を入力して下書き／公開を保存できる。必須不足、不正な日付、未来日、不正な画像 ID、配列などの不正入力は変更を伴わず拒否され、秘密情報を含まない日本語の説明が出る。
- [x] AC-03: 公開した記事は既存の TOP 最新 5 件、お知らせ一覧 10 件、月別表示へ反映され、本文・画像・日付の表示形式と支店表示モードが維持される。公開済み記事の編集も同じ場所へ反映される。
- [x] AC-04: 下書き・ゴミ箱の記事は TOP、一覧、月別候補、検索、旧 URL の直接指定から表示されない。新用記事が旧テーマ、標準 REST、RSS、サイトマップへ混入しない既存境界を保持する。
- [x] AC-05: ゴミ箱へ移動しても ID と内容は保持され、復元で元の状態へ戻る。ゴミ箱内の記事も URL を予約し、削除・別記事作成・復元の順で URL が衝突しない。恒久削除や標準ゴミ箱の自動消去の対象にはしない。
- [x] AC-06: 新規記事は専用の一意識別子と変更しない URL 名を持つ。二重送信で同じ記事が複数作られない。既存記事の取り込み識別子と由来のハッシュは編集前後で変わらない。
- [x] AC-07: 変更操作は管理者権限・対象を限定した nonce・POST を必要とし、別データ種別、旧記事、所属不明、重複識別の ID を指定しても保存されない。画面のタイトル・本文・エラー表示は適切にエスケープされる。
- [x] AC-08: 同じ記事を二画面で開いて先に片方を保存した後、古い画面から保存・ゴミ箱移動・復元すると競合として停止する。途中失敗では部分保存を公開せず、元の完全な状態を保持する。
- [x] AC-09: 旧記事・固定ページ・コラム・フォーム・画像の行と設定は保存前後で変わらず、共存用お知らせの対象行と必要な専用メタだけが変更される。テーマ切替による設定書換え・インポート再実行・パーマリンク再生成は発生しない。
- [x] AC-10: PHP 7.4.33 で構文・対象動作を確認し、外向き通信を止めた隔離環境で権限、競合、途中失敗、公開境界を検証する。管理画面を 375px／1920px で操作できる。本番へのファイル配布は DB 変更・バックアップ・試験記事の作成・テーマ切替を伴わず、本番の実公開確認はユーザーが行う。

## 4. 情報設計と保存契約

| 要素 | 契約 |
| --- | --- |
| 対象 | `exr_news`、保存状態 `exr_stored`、共存データ集合 `exterior-exone-renewal:v1` の所有が一意に確認できる記事だけ |
| 表示状態 | `_exr_source_status` をお知らせに限って現在の `publish` / `draft` / `trash` として管理する。実際の投稿状態を標準 publish / draft / trash に移さない |
| 公開条件 | 既存の所属・状態・`_exr_import_state=complete`・現在以下の表示日時という条件を維持する |
| 既存識別 | `_exr_source_key`、`_exr_dataset`、元の source hash / fingerprint / parent 情報などの取り込み由来は保持する。編集後の内容を元の取り込みハッシュに偽装しない |
| 新規識別 | `exterior-exone-renewal:v1:admin:news:<UUID>`。インポートの `post:news:<元ID>` 形式を使わない。取り込み時の由来ハッシュを捏造しない |
| URL | 新規は UUID 由来の URL 名を自動付与し編集不可。既存名も保持し、全状態で一意性を保つ。個別 URL は既存仕様どおり一覧へ案内し、詳細ページは追加しない |
| ゴミ箱 | 復元前の公開／下書き状態を専用情報として保持。復元時も一意性・所属・現在状態を再確認する |
| 安全な保存 | 古い編集画面を識別する改ざん耐性のある版情報を使い、保存直前にも現在値と対象所有を確認する。複数項目の一体性と二重新規作成の防止を担保する |
| その他 | コメント・トラックバックは閉じたまま。サイト設定、権限、ユーザー、他の投稿型や添付実体は変更しない |

公開面は既存 `front-page`、`archive-news`、月別 `?ym=YYYY-MM` を使用する。新しいデザイン素材、外部サービス、公開用 JavaScript は不要。管理画面の画像選択に標準メディア機能を使用できる。

## 5. スプリント

S1 は F-01 の一機能。専用管理機能、意味のある回帰テスト、独立評価、対象ファイルのみの配布準備を含める。AC は確認した項目だけ合格にし、ユーザーが担当する本番のテーマ切替・実公開確認を完了扱いにしない。

配布時はユーザーの今回の指示に従いバックアップを作成しない。直前の読み取りで対象テーマ・PHP・元ファイルハッシュを確認し、確定した新テーマ内のファイルだけを配置する。旧テーマや DB は配布処理で変更しない。
