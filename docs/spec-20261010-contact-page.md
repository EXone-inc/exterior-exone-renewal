## 1. 背景・目的

- ヘッダー・ドロワー・フッター・支店ヘッダーの「CONTACT / お問い合わせ」がいまはすべて `#`（`inc/menus.php`）で、問い合わせの受け口が無い。カンプどおりの `/contact/` を用意し、来訪者が「個人 / 法人」→「支店」→「方法（メール / LINE / 電話）」を順に選んで、適切な窓口に連絡できるようにする
- 支店サイト（支店ページ・`?store=<slug>` の支店モード）から来た来訪者は、**その支店が最初から選ばれた状態**で開く（ユーザー指示。例: 仙台支店ページの CONTACT → 「個人のお客様」+「仙台支店」が選択済みで、お問い合わせ方法のボタンまで開いている）
- メールでの相談は Contact Form 7（以下 CF7。6.1.5 を導入・有効化済み）のフォームで受け、個人は選んだ支店のアドレス、法人は本社のアドレスへ届ける。フォームの雛形はテーマのコードを正とし、本番にも同じ手順で登録できるようにする

## 2. スコープ

### やること
- 固定ページ `contact`（ID 78、作成済み）を表示する `page-contact.php` と、その FV・タイトル・リード・個人 / 法人ボタン
- 選択フロー: 個人 → 店舗 6 → 方法 3（メール / LINE / 電話）→ 個人フォーム or 電話ブロック、法人 → 法人フォーム。ホバー・選択中の色反転、出現のフェード、画面外に現れたブロックへの自動スクロール
- `?store=<slug>` での初期選択（個人 + その支店 + 方法ボタンまで表示）
- ヘッダー（コーポレート PC のグローバルナビ・支店 PC の CONTACT ボタン）・ドロワー・フッターの CONTACT / お問い合わせを `/contact/` に接続（支店モードでは `?store=<slug>` 付き）
- CF7 のフォーム 2 本（個人・法人）をテーマのコードから登録する関数、支店別の宛先差し替え、自動返信、CF7 の CSS を読まない・CF7 の JS は `/contact/` だけ
- フォームの見た目（テーマの CSS）、入力チェックと項目下のエラー表示、同じページ内の確認表示、完了メッセージ
- SP（375）とタブレット幅の補間、支店モード、`CLAUDE.md` のフレーム対応表への CONTACT 行の追記
- 公開前チェックリスト（§7）

### やらないこと（範囲外）
- 迷惑メール対策（reCAPTCHA 等）の導入（決定 §3。公開前チェックリストで本番に設定）
- 同意チェックボックス・プライバシーポリシーへのリンク（決定 §5-7。カンプどおり付けない）
- 実アドレスの設定（支給待ち。仮アドレスで実装し、公開前チェックリストで差し替え）
- 確認画面・完了画面の別 URL 化（同じページ内で行う。決定 §2）
- 問い合わせ内容の DB 保存（Flamingo 等のプラグイン追加はしない）
- 支店ページの CTA（LINE / 電話の 2 ボタン）やハイエンドページの CONTACT ボタン（`inc/highend-data.php` の `url` が `#`）の行き先変更（オープン論点 Q12）
- フッター STORE・支店データ `exterior_exone_stores()` の並び順の変更（CONTACT だけカンプ順で並べる。決定 §4）
- 東京オフィス（下書き）の表示
- 画像の最終調達（FV 写真・アイコンはカンプの書き出し。FV 写真は AI 生成の**差し替え前提の仮画像**）

## 6. オープン論点（Planner が判断できなかったこと。括弧内の既定で実装し、Generator は**勝手に変えず報告に含める**。呼び出し側でユーザーに確認する）

決定 §5 で「報告で確認」とされた項目は Q2〜Q4・Q14・Q15 に転記した。

- Q1（要確認・カンプに無い状態）: エラー表示の赤の値（`--color-error`）。**既定: #d93025 前後の、地 #f3f3f4 と白の入力欄の上で読める赤**。Generator は採用した値をスクリーンショット付きで報告する

- Q3（要確認・アニメーション。決定 §5-11）: 新しく現れた段への自動スクロール。**既定: 段の上端が画面外（下）のときだけ、その段が見えるまで滑らかにスクロール**。代案: スクロールしない / 常に段の上端まで
- Q4（カンプから決まらない）: 選択状態を URL に反映するか（再読み込み・共有で復元）。**既定: 反映しない**（`?store=` で来たときの初期選択だけ）
- Q5（カンプから決まらない）: `?store=` で開いたとき、読み込み時に方法ボタンまでスクロールするか（PC の支店モードでは方法ボタンが 1 画面目の下に隠れる）。**既定: スクロールしない（FV から見せる）**。代案: 方法の段までスクロール

- Q7（要確認・文面）: 自動返信の本文。**既定: Generator が案を作る（挨拶 / 受付の旨 / 担当支店名（個人）/ 入力内容の控え / 署名「エクステリア工房 EXone」/ 送信専用アドレスの注意書き）**。文面は報告に全文を載せる
- Q8（運用）: 登録関数を再実行したとき、管理画面で直した文面・宛先を上書きするか。**既定: 上書きしない（既存があれば ID を返すだけ）。引数で明示したときだけテーマの雛形で上書き**
- Q9（カンプに無い状態）: JS が無効なときの表示。**既定: 店舗・方法の段・電話ブロック（初期選択の支店。無ければ出さない）・両フォームをすべて表示する。個人フォームは隠しフィールドが空なら本社宛（Q6）**。代案: 2 択だけ出して「JavaScript を有効にしてください」
