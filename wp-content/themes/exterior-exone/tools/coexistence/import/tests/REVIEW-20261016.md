## 判定

この範囲で未解決の P1 / P2 はない。S2 全体の合格判定は保留。実 DB の transaction / rollback / 冪等性、および未完了データが HTTP 経由で公開されないことは、別途隔離環境での統合結果を必要とする。

- P2 修正確認: `dry-run` で新規作成と再利用が混在すると、以前は再利用行の実内容検証を省略して成功した。Generator が仮 ID 採番前に混在計画を拒否する変更を実施。全件新規・全件再利用は従来の検証へ進む。独立した回帰試験でも確認した。
- 既存行の更新は今回取得した新 ID の所有検証で SQL 発行前に拒否。options / users / usermeta / comments / commentmeta への INSERT も SQL 発行前に拒否する。
- 旧 11 テーブルの既存行の変更、共有テーブルへの新規行追加を保護スナップショットで検出。SQL 文へ本文を埋め込まず、値をバインドする。
- 新フォームの保存型は `exr_form`。旧 CF7 型を新 identity として扱う経路、公開状態の新フォーム、重複 identity を拒否する。
- メディアの経路逸脱、symlink、途中で変わった元ファイル、変更された再利用先、未申告ファイルを拒否。通常失敗の取り消しは今回作成した inode のみを対象とし、置換された別ファイルを削除しない。
- CLI の不正な確認値・任意 DB 引数・重複引数・不正な失敗指定は、環境確認や DB 接続の前に停止し、入力中の合成メール本文を出力しなかった。

## 残る運用上の制約

メディアの 1 ファイル作成後に子プロセスを終了し、例外処理を通らない中断を再現した。旧ファイルは保持され、次の実行は既存パス衝突として停止した。中断時の新規ファイルを自動回収・再開する機能は今回確認していない。残存ファイルを既存の正しいファイルと推測して再利用・削除しないため、手動点検が必要。

これは通常の捕捉可能な例外の rollback と区別する。強制終了からの自動復旧を仕様にない追加必須条件としては扱わないが、本番公開可能・全状況で復元済みという判断には使用できない。

読取レビューで確認した guard は、固定ディレクトリ・sentinel・PHP バージョン・socket・database・prefix・TCP 無効・datadir・home / siteurl を照合し、任意接続先の指定を受け付けない。実接続での拒否確認と保護行の実 DB 比較は親担当の統合試験へ引き継ぐ。
